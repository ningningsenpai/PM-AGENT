# PM-Agent 测试规划 Skill

## 触发场景

当用户提出以下类型请求时使用本 Skill：

- 设计模块测试方案、验收用例、冒烟测试；
- 设计后端接口测试、前端页面交互测试、Agent 场景测试；
- 定义 LLM 输出是否符合预期、Prompt 改动后的回归样例；
- 设计压测场景、返回结果检查、质量门禁；
- 判断当前阶段是否需要自动化测试、CI、Playwright / Cypress。

## 目标

帮助 Claude 为 PM-Agent 制定实用、轻量、贴合阶段的测试策略。开发早期以手动验收和关键路径检查为主，MVP 业务逻辑稳定后再逐步补自动化测试。

---

## 一、测试策略基线

| 项 | 决策 |
|---|---|
| 第一版测试方式 | 以手动验收为主 |
| 自动化测试 | MVP 完成、业务逻辑稳定后再补 |
| 后端测试 | 使用已安装的 IDE 插件辅助测试 |
| 前端 E2E | 第一版不引入 Playwright / Cypress |
| Agent 固定样例集 | 需要，但开发前期暂不强制；MVP 完成或开发刚需时建立 |
| CI 流程 | 第一版不需要 |

---

## 二、测试范围

| 范围 | 第一版策略 |
|---|---|
| Java 后端接口 | 手动调用 + 插件测试，关注返回结构、错误码、traceId、幂等 |
| 权限与登录 | 手动验收登录 / 未登录 / 无权限场景 |
| 项目/需求/任务/风险 | 按业务流程检查状态、数据落库、异常分支 |
| Vue 前端页面 | 手动操作路径验收 |
| Agent 服务 | 先测 Prompt 效果、工具调用结果、Trace 是否完整 |
| LLM 输出 | 固定少量样例，人工判断是否符合预期 |
| 压测 | 仅对部分场景需要，如列表查询、Agent 调用、批量任务 |

---

## 三、每个功能完成后的必跑检查

1. **业务流程检查**：从入口到结果完整走一遍；
2. **返回结果检查**：响应结构、错误码、traceId、中文 message 正确；
3. **数据落库检查**：主表、状态日志、Trace、字典引用是否符合预期；
4. **权限检查**：未登录 / 无权限 / 有权限三类路径；
5. **幂等检查**：写接口重复提交同一 `X-Idempotency-Key` 不重复落库；
6. **异常检查**：参数缺失、非法状态流转、资源不存在；
7. **LLM 场景检查**：对 Agent 能力检查输出是否符合预期、是否触发人工确认、Trace 是否记录。

---

## 四、手动验收用例格式

```markdown
## 用例：[用例名称]

- 所属模块：
- 前置条件：
- 操作步骤：
  1. 
  2. 
  3. 
- 预期结果：
- 需要检查的数据：
- 异常分支：
- 是否涉及 Agent：是/否
- 是否涉及幂等：是/否
- 是否涉及压测：是/否
```

---

## 五、Agent 场景测试

Agent 场景测试不是追求每次输出文字完全一致，而是检查关键结构和业务结论：

| 检查项 | 说明 |
|---|---|
| 意图识别 | 是否识别用户真正目标 |
| 工具选择 | 是否调用正确工具 |
| 入参构造 | projectId、taskId、时间范围等是否正确 |
| 业务结论 | 风险等级、任务拆解、周报摘要是否合理 |
| 人工确认 | 高风险动作是否标记需确认 |
| Trace | Prompt、工具调用、模型输出是否落库 |

MVP 稳定后建立固定样例集，覆盖：项目问答、需求拆解、风险识别、周报生成、工具失败。

---

## 六、测试方案输出格式

设计测试方案时，按以下结构输出：

```markdown
# 测试方案：[模块名称]

## 测试目标
## 测试范围
## 不测范围
## 测试数据
## 手动验收用例
## 接口测试用例
## 前端交互用例
## Agent 场景用例
## 异常与边界场景
## 幂等检查
## 压测检查（如需要）
## 回归检查点
## 验收标准
## 待确认问题
```

---

## 七、工作流程

1. 先判断当前模块属于哪个阶段，避免提前设计重型测试体系；
2. 第一版优先写手动验收用例，不强制自动化；
3. 每个业务模块至少覆盖正常路径、异常路径、权限路径、幂等路径；
4. Agent 能力必须覆盖工具调用、Trace 和人工确认；
5. 只有在用户明确要求或业务稳定后，才规划 Playwright / Cypress / CI；
6. 压测只针对明确有性能风险的场景，不默认全量压测。

---

## 八、不可越界

以下事项必须先经用户确认：

- 第一版引入 CI 流程；
- 第一版引入 Playwright / Cypress；
- 强制所有 Controller / Service 都配自动化测试；
- 为追求覆盖率而阻塞 MVP 开发；
- Agent 测试只看文案不检查工具调用和 Trace；
- 压测范围扩大到所有接口。
