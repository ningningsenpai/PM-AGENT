# PM-Agent 成本优化 Skill

## 触发场景

当用户提出以下类型请求时使用本 Skill：

- 评估运行时 LLM API 成本、月度预算、调用频次；
- 设计模型路由、供应商适配层、降级策略；
- 优化 Prompt、上下文长度、缓存、Trace 存储；
- 评估向量库、文件存储、云服务器、中间件部署成本；
- 判断某个 Agent 能力是否值得使用高成本模型；
- 规划本地模型或低成本模型作为后续扩展。

## 目标

帮助 Claude 在保证 PM-Agent 效果的前提下控制 LLM、数据库、中间件和部署成本，适配单人 + AI 开发、运行时月预算约 600 元人民币的现实约束。

---

## 一、成本边界

| 项 | 决策 |
|---|---|
| 运行时 LLM API 月成本上限 | 约 600 元人民币 |
| 开发工具成本与运行成本 | 项目开发完成前不分开计算；完成后可拆分统计 |
| 默认低成本模型 | 接受国产低成本模型，但按不同模型优势选择 |
| 统一模型供应商适配层 | 需要 |
| 本地模型 | 后续扩展考虑，暂不纳入开发阶段 |
| Agent Trace Prompt / 输出 | 需要保存，重点保存自然语言交互部分 |

---

## 二、模型分层策略

| 场景 | 默认模型 | 升级条件 |
|---|---|---|
| 意图识别 | DeepSeek | 识别不稳定或多轮上下文复杂 |
| 普通项目问答 | DeepSeek | 涉及复杂推理或重要决策 |
| 需求拆解 | DeepSeek 起草 | 拆解质量差时升级 Claude / GPT |
| 周报生成 | DeepSeek 草稿 | 最终润色可升级更强模型 |
| 风险分析 | DeepSeek / Claude | 关键风险判断可升级 |
| RAG 问答 | 第 6 阶段再细化 | 取决于召回质量和上下文长度 |

原则：默认模型不等于最强模型，按任务价值选择模型。高成本模型只用于复杂推理、最终润色和关键决策。

---

## 三、统一模型适配层

需要为不同模型供应商设计统一适配层，但不代表第一版接入所有供应商。

### 3.1 适配层职责

- 统一请求参数：model、messages、temperature、stream、max_tokens；
- 统一响应结构：content、usage、finish_reason、error；
- 统一流式输出事件；
- 统一错误重试与降级；
- 统一成本统计；
- 统一 Trace 记录。

### 3.2 接入顺序

1. 第一版运行时默认接 DeepSeek；
2. 后续按质量与成本需要接入 Claude / GPT / Gemini；
3. OpenAI-compatible API 暂不作为强制要求，避免因为兼容层提前复杂化或增加成本；
4. 本地模型作为后续离线 / 低成本模式预留。

---

## 四、缓存策略

优先缓存可复用、非强实时结果：

| 场景 | 缓存建议 |
|---|---|
| 周报草稿 | 按项目 + 时间范围 + 输入摘要缓存 |
| 风险分析结果 | 按项目 + 数据版本缓存 |
| 文档切片摘要 | 第 6 阶段缓存 |
| Prompt 模板 | 本地配置缓存 |
| 字典 / 术语表 | 前后端均可缓存 |

禁止缓存：权限敏感结果、包含未脱敏隐私数据的输出、高风险动作确认结果。

---

## 五、Trace 存储成本控制

1. 开发和调优阶段保留完整 Prompt、模型输出、工具调用结果；
2. Agent Trace 默认保留 3 个月；
3. 大字段可设置阈值，超过后截断并记录 `truncated=true`；
4. 第 6 阶段引入 MinIO 后，可将超大原文外挂存储；
5. 敏感字段脱敏后再入库；
6. 成本评估时同时估算 MySQL 存储增长，而不只看 LLM token。

---

## 六、成本评估输出格式

评估某个能力或模块成本时，按以下结构输出：

```markdown
# 成本评估：[能力/模块名称]

## 调用场景
## 所属阶段
## 成本来源
| 来源 | 说明 | 估算方式 |
|---|---|---|

## 模型选择
## 调用频次估算
## Token / 存储估算
## 缓存策略
## 降级策略
## 质量风险
## 推荐方案
## 后续优化点
## 待确认问题
```

---

## 七、工作流程

1. 先确认能力属于哪个阶段，避免为后置能力提前做成本工程；
2. 明确调用频次、输入长度、输出长度、是否流式；
3. 先用默认低成本模型估算，再评估升级模型收益；
4. 识别可缓存部分和不能缓存部分；
5. 同时估算 LLM token、Trace 存储、中间件和部署成本；
6. 给出推荐方案时说明质量损失和风险；
7. 若成本超过 600 元/月预算，必须给出降级或限流策略。

---

## 八、不可越界

以下事项必须先经用户确认：

- 默认运行时模型改为高成本模型；
- 提前接入多个模型供应商导致适配层过重；
- 第一版纳入本地模型开发；
- 取消 Agent Trace 中自然语言交互 Prompt / 输出保存；
- 忽略 600 元/月运行预算；
- 为省成本牺牲关键业务决策质量但不说明风险；
- 把第 6 阶段 RAG 成本提前当作第一版必做成本。
