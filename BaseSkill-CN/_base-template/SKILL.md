# Skill 名称

## 触发场景

当用户提出以下类型请求时使用本 Skill：

- 场景 1；
- 场景 2；
- 场景 3。

## 目标

说明该 Skill 要帮助 Claude 完成什么工作，以及为什么需要这个 Skill。

## 工作原则

1. 优先对齐项目已有约束，避免凭空设计。
2. 输出必须可执行、可落地，避免泛泛而谈。
3. 重要设计要说明取舍理由。
4. 如果信息不足，先列出关键问题，不要直接假设。

## 工作流程

1. 明确用户目标和当前阶段。
2. 检查已有项目约束、技术栈和目录结构。
3. 给出结构化方案。
4. 明确后续行动项、风险点和验收标准。

## 输出格式

默认使用 Markdown，建议结构：

```markdown
# 标题

## 背景
## 目标
## 方案
## 开发步骤
## 风险与取舍
## 验收标准
## 待确认问题
```

## 待用户回答的问题

1. 这个 Skill 主要服务哪个开发阶段？
2. 使用这个 Skill 时，最希望输出什么类型的结果？
3. 是否有固定的项目命名、目录结构、代码风格或文档格式？
4. 哪些内容必须严格遵守？
5. 哪些内容允许 Claude 自行判断？
