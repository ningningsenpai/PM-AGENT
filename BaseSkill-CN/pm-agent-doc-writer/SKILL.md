# PM-Agent 文档写作 Skill

## 触发场景

当用户提出以下类型请求时使用本 Skill：

- 撰写、整理、重构 `docs/` 下的项目文档；
- 输出需求文档、技术方案、接口规范、数据模型文档、模块设计文档；
- 编写 README、部署说明、项目展示 / 作品集说明；
- 将零散讨论整理成正式 Markdown 文档；
- 统一文档结构、标题层级、术语、验收标准和待确认问题。

## 目标

帮助 Claude 为 PM-Agent 输出统一风格、结构清晰、可维护的中文 Markdown 文档，支撑单人 + AI 开发过程中的设计、实现、复盘和展示。文档要服务开发，不写空泛口号。

---

## 一、文档目录与类型

所有项目文档统一放在 `docs/` 目录。

| 文档类型 | 说明 |
|---|---|
| 产品需求文档 | 模块目标、用户、范围、验收标准 |
| 技术方案 | 架构、分层、接口、取舍、风险 |
| API 接口文档 | 请求、响应、错误码、权限、示例 |
| 数据库设计文档 | 表、字段、索引、枚举、约束 |
| 模块设计文档 | 每个模块必须有设计文档 |
| Agent 设计文档 | Prompt、工具、Trace、模型策略 |
| 测试验收文档 | 手动验收、关键路径、Agent 样例 |
| 部署说明 | 环境、启动、配置、依赖 |
| 项目展示文档 | 用于作品集或对外介绍 |

不需要阶段性项目总结模板；如后续确需总结，可按具体阶段临时生成。

---

## 二、文档工具与接口文档策略

1. API 文档需要额外维护 Markdown 文档，不能只依赖 Knife4j；
2. Knife4j 作为保留选项，用于接口查看和调试辅助；
3. 接口测试采用 IDEA 自带插件或其他已安装插件，不在文档中强制 Postman / Apifox；
4. 每个模块必须有设计文档，代码实现前先完成最小设计说明；
5. 文档风格偏正式技术方案，不写开发日记式流水账。

---

## 三、写作风格

1. 所有文档使用中文 Markdown；
2. 标题清晰、层级稳定，不堆过深小节；
3. 重要设计必须说明背景、目标、方案、取舍、验收标准；
4. 表格用于字段、接口、状态、对比，不要滥用；
5. 每篇文档结尾保留“待确认问题”，但只列真正影响实现的问题；
6. 文档不写历史代码细节，只写当前设计目标、方案、规则、验收标准；
7. 术语必须对齐 `docs/00-术语表.md`。

---

## 四、标准文档结构

默认使用以下结构；可根据文档类型删减，但不要失去背景、方案、验收标准和待确认问题。

```markdown
# 文档标题

## 1. 背景
## 2. 目标
## 3. 范围
### 3.1 本期范围
### 3.2 不做范围

## 4. 详细设计
## 5. 开发计划
## 6. 风险与取舍
## 7. 验收标准
## 8. 待确认问题
```

---

## 五、模块设计文档要求

每个模块设计文档至少包含：

```markdown
# 模块设计：[模块名称]

## 背景
## 模块职责
## 涉及术语
## 业务流程
## 数据模型
## 接口清单
## 前端页面
## Agent 介入点
## 权限与风险
## 开发步骤
## 验收标准
## 待确认问题
```

---

## 六、接口文档要求

API Markdown 文档必须包含：

- 接口路径（含 `/api/v1/`）；
- 请求方法；
- 权限要求；
- 请求头（特别是 `X-Trace-Id`、`X-Idempotency-Key`）；
- 请求参数；
- 响应结构；
- 错误码；
- 示例；
- traceId 说明。

---

## 七、项目展示文档要求

项目展示 / 作品集说明文档要突出：

1. 项目解决的问题；
2. 技术栈；
3. 核心功能；
4. Agent 能力亮点；
5. 架构图或流程图；
6. 可演示路径；
7. 后续规划。

避免夸大未完成能力，未落地的内容标为规划。

---

## 八、工作流程

1. 先确认文档类型和目标读者；
2. 检查 `docs/README.md` 和术语表，确认命名与目录；
3. 读取相关 Skill 或设计文档，避免凭空生成；
4. 按正式技术方案风格组织内容；
5. 输出后检查是否有范围、取舍、验收标准、待确认问题；
6. 若文档中出现新增业务术语，提示先更新术语表。

---

## 九、不可越界

以下事项必须先经用户确认：

- 将项目文档移出 `docs/`；
- 只依赖 Knife4j 而不维护 Markdown API 文档；
- 新增模块但不写模块设计文档；
- 把未实现能力写成已完成；
- 与 `pm-agent-backend-architect` 的日志/API 规范冲突；
- 使用未进入术语表的新术语。
