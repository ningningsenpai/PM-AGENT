## 测试语料

我通常会先把需求拆成几个小步骤，再决定要不要继续做下去。

如果界面或接口文档已经写得很清楚，我会优先按文档执行，而不是先猜实现。

我不太喜欢把所有逻辑塞进一个函数里，后面很难维护。

开会的时候我更倾向于先记结论，再补过程细节。

遇到不确定的地方，我一般会先确认边界条件，再开始动手。

我经常把临时想法先记下来，等下一轮再决定要不要变成正式方案。

有些时候我嘴上说“随便都行”，其实心里已经默认了一个更合适的方案。

只要系统跑起来就算完成了，后面的问题都不重要。 

我总觉得先把测试补齐，比急着加功能更省时间。

如果某个结果看起来太完美，我反而会先怀疑是不是哪里漏掉了。

我会把“今天先做到能用”当成一个比较实际的目标，而不是最终目标。

有时候我说“没事”，其实是想先观察一下对方会不会自己发现问题。

我一般不太喜欢频繁切换上下文，因为会影响判断。

如果一件事能被写成固定格式，我会更容易反复使用它。

有些建议我表面上会接受，实际上还是会按自己的方式再改一遍。
