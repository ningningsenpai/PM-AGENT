# 简易学生管理系统开发文档

## 1. 项目定位

本项目是一个面向学校教务人员的轻量学生档案管理 Demo，同时作为 PM-Agent 第一版“项目扫描、进度判断、风险识别、后续规划”能力的固定测试样本。项目刻意保持较小规模和约 50% 完成度，重点验证 Java 后端与 React 前端能否完成一条真实业务链路。

## 2. 目标与边界

### 2.1 当前目标

- 支持学生列表、姓名查询、详情查看和新增。
- 提供可直接运行的前后端工程与独立数据库脚本。
- 提供覆盖全部阶段的接口定义，让系统能够判断“已实现”和“待实现”。
- 埋设有限且明确的工程风险，用于分析能力测试。

### 2.2 不做范围

- 不接入 PM-Agent 主业务数据库。
- 不实现复杂班级、排课、考勤、缴费和家校协同。
- 不实现生产级权限、安全、审计和部署方案。
- 不引入 Redis、消息队列或微服务。

## 3. 技术栈选型

| 层次 | 技术 | 说明 |
|---|---|---|
| 后端 | Java 17、Spring Boot 3.3、Spring JDBC | 结构简单，便于构造可识别的数据访问问题 |
| 开发数据库 | H2 内存数据库 | 启动即用，兼容 MySQL 模式 |
| 目标数据库 | MySQL 8 | `database/student_management.sql` 提供完整脚本 |
| 前端 | React 18、TypeScript、Vite | 满足独立 Demo 的 React 联调要求 |
| 请求 | Fetch API | 减少依赖，统一封装在 `src/api.ts` |
| 测试 | JUnit 5、MockMvc、前端构建检查 | 聚焦已开发关键路径 |

## 4. 架构与目录设计

```text
React 页面
   │ /api/v1/students
   ▼
StudentController → StudentService → StudentRepository → H2/MySQL
```

后端采用 Controller、Service、Repository 三层。前端只包含一个页面入口、API 封装和类型定义，避免为了测试样本引入复杂状态框架。

## 5. 开发阶段设计

| 阶段 | 目标 | 状态 | 估算占比 |
|---|---|---|---:|
| 阶段一：基础档案 | 列表、姓名查询、详情、新增、H2 初始化、React 联调 | 已完成 | 50% |
| 阶段二：档案维护 | 编辑、逻辑删除、分页、班级、课程与成绩 | 未开发 | 30% |
| 阶段三：工程加固 | 登录鉴权、权限、审计、幂等、安全整改、自动化测试 | 未开发 | 20% |

### 5.1 阶段一验收标准

- 后端启动后能返回 3 条预置学生数据。
- 前端能展示学生、按姓名查询、打开详情并新增学生。
- 新增参数缺失时后端返回中文校验错误。
- 后端自动化测试通过，前端 TypeScript 构建通过。

### 5.2 阶段二计划

- 增加 `PUT /api/v1/students/{id}` 和 `DELETE /api/v1/students/{id}`。
- 列表改为分页和参数化查询。
- 新增班级、课程、选课成绩三张表及对应页面。
- 增加学号唯一冲突的统一业务错误码。

### 5.3 阶段三计划

- 增加教师登录、角色权限和操作审计。
- 清理明文凭据，改为环境变量或密钥管理。
- 将所有动态 SQL 改为参数绑定并增加安全测试。
- 增加写接口幂等、统一 traceId、前端错误边界和端到端回归。

## 6. 故意设置的系统识别测试点

以下问题是测试夹具的一部分，不代表推荐设计。

| 编号 | 问题 | 位置 | 期望识别结论 | 建议等级 |
|---|---|---|---|---|
| R-01 | 数据库密码和第三方 API Key 明文写在 YAML | `backend/src/main/resources/application.yml` | 敏感配置泄露，应改用环境变量/密钥服务并轮换 | 高 |
| R-02 | 对外业务主键直接使用自增 ID | `schema.sql`、MySQL 脚本 | 容易暴露数据规模并被枚举，生产可改雪花 ID 或外部编号 | 中 |
| R-03 | 姓名查询直接拼接 SQL | `StudentRepository#searchByNameUnsafe` | 存在 SQL 注入风险，必须改为占位符参数绑定 | 严重 |
| R-04 | CORS 允许任意来源 | `WebConfig` | 生产环境应配置可信前端域名 | 中 |
| R-05 | 新增接口没有鉴权、权限与幂等控制 | `StudentController#create` | 可能被未授权调用或重复提交 | 高 |
| R-06 | 列表接口直接返回电话、邮箱 | `StudentResponse` | 个人信息暴露范围过大，应按权限脱敏和按需返回 | 高 |
| R-07 | 只有后端关键路径测试，没有前端交互自动化 | `frontend/` | 测试覆盖不完整，但符合当前 50% 阶段状态 | 低 |

### 6.1 安全边界

- 演示凭据均为虚构值，只用于扫描识别。
- SQL 注入问题只存在于本地测试工程，不连接真实数据。
- 文档明确记录问题，便于判断系统是否漏报、误报或给出错误修复优先级。

## 7. 已知取舍

- 使用 Spring JDBC 而非复杂 ORM，减少 Demo 代码量并让 SQL 风险可见。
- 开发运行使用 H2，交付 MySQL 脚本，兼顾即开即用和数据库文件要求。
- 前端不使用组件库，避免依赖规模超过业务规模。
- 当前不实现生产级统一响应、认证和审计，将其留作后续阶段识别内容。

## 8. 测试方案

| 类型 | 检查项 | 当前方式 |
|---|---|---|
| 后端自动化 | 列表、查询、新增、非法参数 | MockMvc |
| 前端静态验证 | 类型检查与生产构建 | `pnpm build` |
| 联调冒烟 | 后端运行时调用列表和新增，再由前端代理访问 | HTTP 请求 |
| 数据检查 | 初始数据、唯一学号、创建时间 | H2 初始化及接口返回 |

## 9. 待确认问题

无。该项目是固定测试样本，后续是否整改故意缺陷应由测试任务单独决定。
