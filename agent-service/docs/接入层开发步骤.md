# Agent 接入层后续开发步骤

本文档记录 Agent 接入层在完成模型原生工具调用之后的后续开发顺序。长期架构与安全边界以根目录 [`docs/06-Agent设计.md`](../../docs/06-Agent设计.md) 为准。

## 1. 当前基线

当前接入层已经具备：

- Bearer JWT 鉴权以及请求用户与登录用户一致性校验；
- JSON 与 SSE 两种响应模式；
- `meta`、`tool_call`、`tool_result`、`token`、`error`、`done` 事件；
- Provider 无关的完整轮次、工具调用和流式增量契约；
- 请求级工具注册表、安全执行器和有限工具循环；
- 首个只读真实工具 `get_current_project`；
- 工具参数、输出、超时和异常的统一收敛；
- 客户端伪造工具消息的请求级拦截。

工具直接调用 Python 业务模块公开 Service，不存在 Java/Python 业务 HTTP 自调用。

## 2. 下一步优先级

### 2.1 前端事件消费

前端 Agent 模块需要按 SSE 事件类型维护展示状态：

1. `meta` 初始化会话与 traceId；
2. `tool_call` 展示工具执行中状态；
3. `tool_result` 根据状态和 `errorCode` 展示安全摘要；
4. `token` 追加最终回答；
5. `done` 保存模型与 token 用量；
6. `error` 结束当前请求并展示中文错误。

前端不得把服务端产生的 `tool_call` 或 `tool` 消息原样提交回对话接口。

### 2.2 Agent Trace 持久化

在引入写工具前补充 Trace 数据模型与 Alembic 迁移，至少记录：

- traceId、用户、项目、会话和轮次；
- Provider、模型和累计 token 用量；
- 工具调用 ID、名称、已脱敏参数、状态、错误标识和耗时；
- 最终回答、整体状态和错误信息。

Prompt 原文、完整工具业务出参和敏感凭据默认不落库。

### 2.3 人工确认与写工具

写工具必须在只读链路稳定后单独实现，并同时满足：

- Service 内权限与资源状态校验；
- `X-Idempotency-Key` 或等价的服务端幂等键；
- 可验证、单次使用且有过期时间的确认凭证；
- Trace 和业务审计记录；
- 用户拒绝、过期、重复确认和执行失败的状态处理。

在上述条件完成前，工具注册表不得注册删除、权限变更或对外通知工具。

### 2.4 Provider 扩展

新增 Provider 时依次实现并测试：

1. 非流式 `tool_calls` 解析；
2. 流式工具名称和 JSON 参数分片聚合；
3. assistant 工具决策与必要推理字段的下一轮回传；
4. token 用量解析；
5. 能力对象声明。

未完成上述验证前，对应能力保持关闭，不通过名称或协议兼容性推断支持。

### 2.5 多场景 Agent

出现第二个真实 Agent 场景后再增加场景路由和公共 Agent 协议。当前仅有项目问答时，不提前引入通用工作流框架。

## 3. 代码边界

| 目录 | 职责 |
|---|---|
| `app/api/v1/agent.py` | HTTP 鉴权、JSON/SSE 协议和流式错误收敛 |
| `app/agents/dependencies.py` | 请求级 Agent、注册表、执行器和业务工具装配 |
| `app/agents/tools/` | 工具抽象、契约、注册和安全执行 |
| `app/llm/contracts.py` | Provider 无关模型轮次与流式事件 |
| `app/llm/clients/` | 厂商协议适配 |
| `app/llm/orchestration/` | 上下文和有限模型—工具循环 |
| `app/modules/<module>/` | 业务规则、权限、事务和持久化 |

Agent 工具不能接收 SQLAlchemy Session 或 Repository。新增跨模块能力时，先补充目标模块公开 Service，再实现薄工具适配。

## 4. 验收标准

- 前端可正确展示工具开始、完成、失败和最终回答状态；
- Trace 落库不保存敏感数据或完整业务返回；
- 任一写工具在缺少确认或幂等条件时无法执行；
- 新 Provider 在能力测试通过前不会收到工具定义；
- 新增 Agent 场景不会改变现有项目问答接口行为。

## 5. 待确认问题

- 人工确认凭证采用独立接口还是复用对话接口，需要在写工具设计前确定。
- Qwen/Ollama 的工具协议适配时机取决于本地模型的实际使用优先级。
