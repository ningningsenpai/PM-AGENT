# 学生管理 Demo 项目分析说明

## 1. 文档目的

本文介绍 `agent-service/project_test` 下的简易学生管理系统测试样本，供 PM-Agent 第一版验证项目扫描、开发进度判断、缺口识别、风险分析和开发计划生成能力。

## 2. Demo 定位

该 Demo 是独立的 Java + React 前后端小项目，模拟一个处于开发中期的学生档案系统。它不属于 PM-Agent 正式业务模块，也不应复用正式系统的数据库或运行配置。

## 3. 当前开发进度

综合代码、接口、页面和测试情况，当前完成度定义为 **50%**。

| 能力 | 状态 | 证据 |
|---|---|---|
| 学生列表 | 已完成 | 后端 GET 接口、React 表格、自动化测试 |
| 姓名查询 | 已完成但有安全缺陷 | 前后端联调代码、拼接 SQL |
| 学生详情 | 已完成 | 后端详情接口、前端侧边档案 |
| 新增学生 | 已完成但工程控制不足 | 表单、POST 接口、参数校验、自动化测试 |
| 编辑与删除 | 未开发 | 接口文档仅定义阶段二契约 |
| 班级、课程、成绩 | 未开发 | 接口文档仅列出计划接口 |
| 登录、权限、审计 | 未开发 | 阶段三规划 |
| 安全与幂等治理 | 未开发 | 已埋设识别测试点 |

## 4. 剩余开发阶段

### 4.1 阶段二：档案维护与教学数据（预计 30%）

1. 增加学生编辑和逻辑删除。
2. 为学生列表增加分页和安全的参数化查询。
3. 建立班级、课程、选课成绩数据模型。
4. 增加课程与成绩的录入、查询页面。
5. 完善业务错误码、重复学号处理和回归用例。

### 4.2 阶段三：工程加固（预计 20%）

1. 引入教师登录和角色权限。
2. 增加写接口幂等、操作审计和统一 traceId。
3. 整改明文配置、SQL 注入、宽松跨域和个人信息暴露。
4. 增加前端交互测试、安全测试和部署配置。

## 5. 问题所在之处

| 风险 | 文件或模块 | 识别重点 |
|---|---|---|
| 明文敏感配置 | `backend/src/main/resources/application.yml` | 数据库密码、第三方 API Key，不应只报普通配置问题 |
| SQL 注入 | `StudentRepository#searchByNameUnsafe` | 用户输入进入 SQL 字符串拼接，风险等级应最高 |
| 可枚举业务 ID | `schema.sql`、`database/student_management.sql` | 自增 ID 暴露规模和枚举入口，需要结合是否对外判断风险 |
| 过宽 CORS | `WebConfig` | `allowedOriginPatterns("*")` 与任意方法组合 |
| 鉴权和幂等缺失 | `StudentController#create` | 写接口无需身份、权限或幂等键 |
| 个人信息暴露 | 学生列表响应与 React 表格 | 电话、邮箱直接出现在列表，缺少脱敏和最小化返回 |
| 阶段实现不完整 | 接口文档与代码差异 | 阶段二、三只设计未实现，不应误判为代码缺失错误 |

## 6. 系统需要识别到的范围

### 6.1 项目结构识别

- 判断该目录包含独立后端、前端、数据库和文档。
- 识别后端为 Spring Boot + Spring JDBC，前端为 React + TypeScript + Vite。
- 区分开发用 H2 与目标 MySQL 脚本。

### 6.2 进度识别

- 以真实代码和测试为“已完成”证据，不能只依据接口文档。
- 将阶段二、阶段三接口归类为计划内容。
- 最终进度应接近文档定义的 50%，并说明判断依据。

### 6.3 风险识别

- 至少识别 R-01 至 R-06 六类问题。
- 将 SQL 注入、明文密钥、未鉴权写接口置于较高修复优先级。
- 明确这些问题只位于测试 Demo，不应错误归因到 PM-Agent 正式后端。

### 6.4 计划生成

- 给出小步、按依赖排序的阶段二和阶段三计划。
- 安全整改应包含参数绑定、密钥轮换、环境变量、可信跨域、认证授权、幂等与数据脱敏。
- 不应建议为该小项目提前引入微服务、Redis 集群、消息队列或复杂基础设施。

## 7. 预期分析结果

一次合格的系统分析应同时回答：项目是什么、用了什么技术、已经完成什么、尚未完成什么、关键问题在哪里、问题优先级如何、下一阶段应按什么顺序推进。只输出漏洞列表或只复述文档均不算完成。
