# 系统架构

## 总体架构

PM-Agent 采用 Vue 3 前端与 FastAPI 模块化单体后端。业务数据、会话协调、项目原文件和模型能力分别由 MySQL、Redis、MinIO 与 LLM 承担。

![PM-Agent 总体技术架构](assets/diagrams/system-architecture.svg)

## 模块职责

| 模块 | 主要职责 | 不承担的职责 |
|---|---|---|
| `auth` / `user` | 注册、登录、注销、JWT 会话、用户资料 | 不保存项目文件或 Agent 上下文 |
| `project` | 项目空间、所有者校验、项目删除编排 | 不直接操作其他模块 Repository |
| `project_file` | 同步计划、文件状态、MinIO 原文、解析与索引更新 | 不在数据库事务中调用 MinIO 或 LLM |
| `chat` | 会话、消息、运行、请求理解、上下文更新与确认 | 不允许模型直接写业务库或对象存储 |
| `report` | 开发/风险报告生成、证据绑定与历史查询 | 不把报告结论写成任务或风险实体 |
| `agents` / `llm` | 工具注册执行、上下文组装、模型适配与有限循环 | 不持有 SQLAlchemy Session，不执行模型生成 SQL |
| `input_context` | 输入归一化、来源路由、排序、证据装配和预算 | 不将召回结果自动视为已核验原文 |

## 数据职责

### MySQL

MySQL 保存用户、项目、项目文件元数据、Agent 会话与消息、运行轨迹、待确认学习草稿和报告。它记录“谁在何时对哪个项目执行了什么”，但不保存项目规则、长短期记忆和用户习惯的正文版本。

### Redis

Redis 管理 JWT `jti` 会话，并为幂等、租约与缓存提供快速协调。它不是业务最终事实的唯一来源。

### MinIO

MinIO 保存项目原文件和 `system/` 下的固定上下文对象。文件 Detail、项目规则、记忆、用户偏好和更新日志使用稳定对象路径，便于 Agent、报告和人工检查读取同一组项目资料。

### LLM

DeepSeek 负责文件语义解析、请求计划和回答/报告生成。模型只接收后端裁剪后的上下文，并且输出必须经过结构校验或业务规则校验后才能进入下一步。

## 请求调用边界

关键约束如下：

- API 不直接访问 MySQL、Redis、MinIO 或 LLM 客户端。
- Repository 不调用其他 Repository，也不调用外部基础设施。
- 跨模块协作使用公开 Service。
- ORM 模型不直接作为 API 响应。
- Python 是业务表的唯一写入者，Alembic 是唯一 Schema 所有者。
- 对象存储和模型调用位于数据库事务之外，通过状态和条件更新完成最终收敛。

## 身份、隔离与追踪

1. 登录后签发 Bearer JWT，并在 Redis 中保存 `jti` 会话；注销后会话立即失效。
2. 项目、文件、会话、上下文、报告与运行读取都先校验当前用户对项目的所有权。
3. 前端请求统一携带 `X-Trace-Id`，后端将 Trace 贯穿业务响应和 Agent 运行记录。
4. 项目文件 ID、对象键和用户输入不能绕过 Service 边界读取其他项目内容。
5. 高风险写入使用幂等键、乐观版本或人工确认，避免重复提交和模型误写。

## 部署结构

默认本地部署包含以下运行单元：

```text
Vue 3 前端 :5173
FastAPI 后端 :8000
MySQL :3306
Redis :6379
MinIO API :9000 / Console :9001
```

Docker Compose 中保留了可选的 `rag` profile，但当前在线召回不依赖它，默认启动命令只启动 MySQL、Redis 和 MinIO。
