# 运行与验证

## 环境要求

| 工具 | 建议版本 | 用途 |
|---|---|---|
| Python | 3.11 或更高 | FastAPI 后端、Alembic 与 Pytest |
| Node.js | 20.x | Vue 3 前端构建 |
| pnpm | 9.x | 前端依赖与脚本 |
| Docker Desktop | 支持 Compose | MySQL、Redis 与 MinIO |
| PowerShell | 7.x | 本地命令示例 |

真实文件语义解析、项目问答和报告生成需要有效的 DeepSeek API Key。只进行代码检查、前端构建或关闭 LLM 的基础接口验证时可以不配置 Key。

## 配置说明

项目提供两份示例配置：

- `deploy/.env.example`：MySQL、Redis、MinIO 端口和本地账号。
- `agent-service/.env.example`：数据库、Redis、MinIO、JWT、文件限制与模型参数。

复制后至少检查以下变量：

| 变量 | 说明 |
|---|---|
| `PM_AGENT_JWT_SECRET` | JWT 签名密钥，必须替换示例值 |
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` | MySQL 本地账号密码 |
| `REDIS_PASSWORD` | Redis 密码 |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | MinIO 本地账号 |
| `DEEPSEEK_API_KEY` | 真实模型调用凭据，不得提交到 Git |
| `PM_AGENT_FILE_DETAIL_LLM_ENABLED` | 是否对上传文件启用语义解析 |

`.env` 只用于本地运行，不应提交。面向公网部署时还需要使用强随机密码、HTTPS、反向代理、访问控制与独立密钥管理服务。

## 启动基础设施

在仓库根目录执行：

```powershell
Copy-Item deploy/.env.example deploy/.env
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d mysql redis minio
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

预期三个服务均进入健康或运行状态。默认只绑定本机地址，不启动可选 `rag` profile；当前在线召回不依赖 Qdrant。

## 启动后端

```powershell
Set-Location agent-service
python -m venv .venv
. .\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

编辑 `agent-service/.env`，确保数据库、Redis 与 MinIO 配置和 `deploy/.env` 一致。如需真实模型调用：

```dotenv
DEFAULT_LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=在本机填写
PM_AGENT_FILE_DETAIL_LLM_ENABLED=true
PM_AGENT_FILE_DETAIL_LLM_PROVIDER=deepseek
```

然后执行迁移并启动服务：

```powershell
python -m alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

后端启动时会检查数据库连接、Alembic 版本和 Redis，并初始化 MinIO 客户端。MinIO 连通性在首次实际操作时校验，因此完成启动后还应通过项目初始化或文件操作检查对象存储。

## 启动前端

另开一个 PowerShell 终端：

```powershell
Set-Location frontend
pnpm install
pnpm dev
```

Vite 将 `/api` 代理到 `http://localhost:8000`。常用入口：

| 地址 | 用途 |
|---|---|
| `http://localhost:5173` | 项目工作台 |
| `http://localhost:8000/docs` | FastAPI OpenAPI |
| `http://localhost:8000/internal/health` | 后端健康检查 |
| `http://localhost:9001` | MinIO 控制台 |

## 建议体验路径

```text
注册并登录
  → 创建项目并选择本地目录
  → 查看同步计划并上传文件
  → 执行文件解析并检查文件级状态
  → 创建项目助手会话
  → 询问项目进度、风险、规则或来源
  → 检查工具来源与运行详情
  → 确认需要沉淀的上下文草稿
  → 生成并查看开发报告或风险报告
```

文件解析和模型问答会将项目文本发送到配置的模型提供方。只应对允许外发的项目资料启用该能力。

## 验证命令

### 后端

```powershell
Set-Location agent-service
python -m pytest
python -m alembic upgrade head --sql
python -m ruff check app tests
```

### 前端

```powershell
Set-Location frontend
pnpm test
pnpm typecheck
pnpm build
```

不同层次的验证目标：

| 层次 | 重点 |
|---|---|
| 单元测试 | 权限、幂等、版本、状态、参数校验、召回和工具边界 |
| 前端契约 | 统一响应、大整数 ID、恢复、错误状态、安全 Markdown 和页面交互约束 |
| 数据库迁移 | 当前模型与 Alembic head 一致，迁移脚本可以生成 SQL |
| 真实链路 | MySQL、Redis、MinIO 实际读写，文件上传解析、会话、工具、上下文和报告可恢复 |
| 人工审阅 | 回答是否忠实于来源、风险措辞是否合理、无答案时是否克制 |

模型输出具有非确定性。自动测试能验证协议、状态和引用存在性，但不能代替对每条自然语言结论的语义审阅。

## 当前能力边界

- 持久化项目会话当前使用 JSON 响应，尚未开放 SSE 路由。
- 文件语义分析当前只支持 DeepSeek；会话模型适配层还声明了其他可选提供方。
- 在线召回使用词法方案，Qdrant 只存在于可选实验 profile 中。
- 任务看板和风险中心尚未形成正式后端状态机。
- 文件删除或路径变化时，文件派生长期记忆的自动失效尚未完全收敛；相关结论应回读当前原文件核实。
- 系统不会自动执行开发任务、修改代码或运行模型生成的 SQL。
- 本地 Compose 适合开发验证，不等同于生产部署方案。

## 停止服务

在仓库根目录执行：

```powershell
docker compose --env-file deploy/.env -f deploy/docker-compose.yml down
```

该命令保留数据卷。删除数据卷会清空本地 MySQL、Redis、MinIO 和可选 Qdrant 数据，不应作为普通停止步骤使用。
