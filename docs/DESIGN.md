# Design System：PM-Agent

## Overview

PM-Agent 是一个面向个人开发者的项目计划、执行追踪、风险规划与 Agent 辅助软件。用户可能同时维护多个项目，但进入项目后，需求、迭代、任务、风险、个人工作台、PM 助手、文件与报告全部绑定当前项目。

产品不以团队协作、成员分工或企业管理为目标。界面中不得出现项目成员、负责人、协作者、成员头像墙、团队负载、部门、审批人或绩效等团队型概念。

产品的核心层级只有两层：

1. **全局层：** 所有项目、站内消息、个人资料和系统设置。
2. **当前项目层：** 个人工作台、需求、迭代、任务、风险、PM 助手、文件与知识、报告和项目设置。

视觉方向以已确认的个人工作台参考界面为基准：浅灰白画布、白色表面、细边框、克制的蓝绿杏状态色、清晰的深色标题、轻量线性图标和紧凑但不拥挤的工作区。产品应显得清爽、可信、可执行，而不是传统企业后台或数据大屏。

信息密度采用“职责单一的适中密度”：减少无效留白，但不把多个模块的完整内容堆在同一页面。交互态、滚动态和抽屉态必须生成独立画面，不能叠加进默认态。

## Colors

### 核心配色

| 角色 | 色值 | 用途 |
|---|---|---|
| 墨黑蓝 | `#172033` | Logo 标记、页面标题、最重要文字与少量高优先级图标 |
| 深蓝灰 | `#2F3A4A` | 主按钮、少量强调操作，不用于大面积背景 |
| 主文字 | `#1F2937` | 正文、卡片标题、导航文字 |
| 次文字 | `#667085` | 说明、元信息、次级操作 |
| 弱文字 | `#98A2B3` | 占位、低优先级时间和辅助标签 |
| 画布 | `#F4F6F5` | 应用主背景 |
| 表面 | `#FFFFFF` | 侧边栏、顶部栏、卡片、浮层 |
| 浅层表面 | `#F7F8F7` | 表头、分段控件、只读信息区 |
| 边框 | `#E6E8E7` | 卡片、输入框、分隔线 |
| 数据蓝 | `#6F9FB7` | 任务、链接、进度、普通信息 |
| 浅蓝 | `#E8F2F7` | 选中导航、轻量信息背景 |
| 薄荷绿 | `#68BFA4` | 正常、完成、健康状态 |
| 杏色 | `#D3A05B` | 风险提示、到期提醒、需要关注 |
| 柔和红 | `#CF6A70` | 逾期、严重风险、删除与失败 |

白色和浅灰约占页面 82%，彩色状态约占 10%，墨黑蓝和深蓝灰实心区域合计不超过 8%。

### 黑色使用边界

墨黑蓝和深蓝灰用于建立视觉锚点，而不是作为大面积配重。

允许使用的位置：

- 左上角 Logo 小标记；
- 页面主标题与重要数字；
- 每屏唯一的主操作，例如“新建项目”；
- 需要强对比的菜单文字和关键图标；
- 图表 Tooltip 的小面积背景。

禁止使用的位置：

- 整块侧边栏或顶部栏背景；
- 大面积卡片、指标卡和日历背景；
- 用户头像背景；
- 普通次级按钮；
- 所有图标统一填黑；
- 大面积图表填充或装饰色块。

同一页面原则上只保留一个深色实心主按钮。Logo 与主按钮以外，不再增加大面积深色块。

### 用户头像配色

用户头像必须保持参考界面中的清浅蓝色，不得改为黑色、深蓝色或高饱和渐变。

- 默认背景：`#EAF4F9`；
- 默认边框：`#D3E6EF`；
- 人物图标或文字：`#6A9CB5`；
- 悬停背景：`#DFEEF5`；
- 键盘焦点环：2px `#A9CFDF`；
- 用户下拉菜单：白色背景、浅灰边框、柔和阴影；
- 左侧底部账户卡：白色背景和浅灰边框，头像继续使用相同浅蓝体系；
- 未读消息使用独立柔和红点，不改变头像底色。

Agent 在线状态与用户头像分开表达：Agent 状态使用薄荷绿圆点与浅绿胶囊，头像仍保持浅蓝。

### 状态色规则

- 蓝色：任务、进行中、普通链接和项目进度；
- 绿色：完成、正常、健康和已解除；
- 杏色：需要关注、风险观察和临近到期；
- 红色：逾期、严重风险、失败和危险操作；
- 所有状态同时提供文字或图标，不依赖颜色单独传达。

## Typography

不引入特殊品牌字体。统一使用常见系统无衬线字体：`Inter`、`Noto Sans SC`、`Microsoft YaHei`、`Arial`、`system-ui`。

- 页面标题：28px / 600；
- 分区标题：18px / 600；
- 卡片标题：15px / 600；
- 正文：14px / 400 / 1.6；
- 导航与按钮：13–14px / 500；
- 元信息：12px / 400；
- 核心数字：28–30px / 600。

界面最多同时出现 400、500、600 三档字重。不使用 700–800 粗体墙，不使用全大写英文，不通过特殊字体制造品牌感。清新感由舒展行高、自然字距、轻量颜色与留白建立。

## Layout

### 应用骨架

- 设计基准：1440×1024，最低宽度 1280px；
- 左侧导航：236px，固定高度 100vh，白色背景；
- 顶部状态栏：52px，固定在内容区顶部，白色背景；
- 主画布：浅灰白背景，左右留白 28px；
- 主内容宽度随视口伸缩，不设置永久右侧栏；
- 页面默认只有一个主要纵向滚动容器。

侧边栏从上到下分为：

```text
Logo 与版本
项目切换器

全局工作
└── 所有项目

项目执行（当前项目）
├── 个人工作台
├── 需求
├── 迭代
├── 任务
└── 风险

智能协作（当前项目）
├── PM 助手
├── 文件与知识
├── 报告中心
└── 会议纪要

底部固定
├── 站内消息
├── 系统设置
└── 用户账户卡
```

“所有项目”位于“个人工作台”之前。个人工作台属于当前项目，不是跨项目工作台。

### 信息密度

- 所有项目页只展示项目入口和关注提醒，不展示项目内部完整内容；
- 概览页最多 3–4 个轻量指标、1 个主要内容区和 1 个摘要区；
- 列表页默认不放大型图表；
- 看板页以看板为唯一主体；
- 详情页只围绕当前对象；
- 右侧信息面板只在选中对象后按需出现；
- 同一页面不同时展示完整列表、完整看板、完整图表与完整活动流。

## Elevation & Depth

- 普通卡片通过白色表面、1px 边框和间距建立层级，不使用明显阴影；
- 卡片悬停仅增加极轻阴影和边框变化；
- 下拉菜单、日历提示框、抽屉和弹窗可以使用柔和阴影；
- 浮层阴影保持中性灰，不使用蓝紫发光；
- 所有项目日历提示框应明显位于日期格上方，但不得像模态框一样压住整页。

## Shapes

- 导航项、按钮和输入框：8–10px 圆角；
- 普通卡片：12–14px 圆角；
- 浮层和提示面板：10–12px 圆角；
- 状态标签：胶囊形；
- 用户头像：圆形；
- 图标：统一 1.5–2px 线性描边，14–18px；
- 禁止混用 3D、拟物、双色填充和线性图标。

## Components

### Logo

Logo 使用小面积墨黑蓝圆角方块与节点连接图形，旁边显示“PM-Agent”。墨黑蓝仅用于标记本身，不延伸为深色侧边栏。

### 项目切换器

项目切换器必须延续参考界面：

- 白色背景、浅灰边框、42px 高、8px 圆角；
- 左侧使用蓝灰色线性文件夹图标；
- 中间显示当前项目名称；
- 右侧使用轻量上下切换图标；
- 悬停只改变边框和浅层背景；
- 点击后打开紧凑下拉层，显示当前项目、最近项目、项目名称搜索和“查看所有项目”；
- 选择项目后切换当前项目并进入该项目个人工作台。

### 左侧导航

- 选中项使用浅蓝背景 `#E8F2F7`；
- 选中文字使用主文字色，不使用黑色实心块；
- 分组标题使用 11–12px 弱文字；
- 导航图标统一线性风格；
- 底部账户卡保持白色边框卡片，不使用深色背景。

### 顶部状态栏

顶部栏包括面包屑、Agent 状态、搜索、主操作、消息和头像。

- Agent 正常状态：浅绿胶囊、绿色圆点和深绿文字；
- 当前项目页面的搜索只搜索当前项目；
- 所有项目页面的搜索只搜索项目名称和描述；
- “新建项目”是页面唯一深色实心主按钮；
- 消息图标保持线性，未读状态使用小红点；
- 用户头像严格使用浅蓝头像令牌。

### 项目卡片

项目卡片只展示：项目名称、状态、当前迭代、整体进度、最近更新时间、今日任务数量、逾期数量、重要风险数量和待确认 Agent 建议。

- 使用白色表面和浅灰边框；
- 需要关注的项目使用 2px 杏色短边线或小圆点，不使用整卡红色；
- 今日无紧急事项时显示轻量绿色状态；
- 卡片不展示任务正文、风险证据、需求列表、成员头像和活动流。

### 视图切换器

“项目列表 / 日历视图”使用紧凑分段控件：白色或浅层背景、浅灰边框、选中项浅蓝底色。不得使用两个大型按钮。

### 日历

- 月视图使用星期一至星期日七列；
- 今天使用浅蓝底或蓝色细边框；
- 非本月日期降低灰度；
- 日期格使用轻边框，不使用厚重办公日历网格；
- 日期格只显示图标和数量，不直接堆叠大量任务文字；
- 蓝色勾选圆图标表示到期任务；
- 红色时钟表示逾期或必须当天处理；
- 杏色警告三角表示需要处理的风险；
- 绿色旗帜表示迭代节点或里程碑；
- 同一日期最多直接显示三行摘要，更多内容显示“+N”。

### 日历悬停提示

- 宽 300–340px，白色背景、浅灰边框、10–12px 圆角；
- 根据空间出现在日期格左侧或右侧，不遮挡触发图标；
- 顶部显示日期和待关注数量；
- 内容按项目分组，展示类型图标、事项标题、时间或状态；
- 最多直接展示 5–6 项，其余显示“查看全部”；
- 不使用全屏遮罩，不扩大为右侧永久栏。

### 用户头像与账户卡

- 顶部头像尺寸 32px，浅蓝背景、浅蓝边框和蓝灰图标；
- 侧边栏底部头像可为 30–32px，颜色完全一致；
- 账户卡内用户名使用主文字色，邮箱使用弱文字；
- 悬停只改变浅蓝背景与边框，不出现墨黑头像底；
- 用户菜单使用白色浮层，不使用深色菜单。

## Do's and Don'ts

### Do

- 以个人开发者为唯一核心用户；
- 明确区分全局“所有项目”和项目内“个人工作台”；
- 让所有项目页快速回答“有哪些项目、今天哪些项目需要关注”；
- 使用项目切换器建立清晰的当前项目上下文；
- 使用浅蓝头像、浅蓝选中导航和低饱和状态色；
- 使用深色标题和一个深色主按钮建立视觉锚点；
- 使用真实、连贯的个人项目样例；
- 为日期图标、风险颜色和进度状态提供文字说明。

### Don't

- 不展示负责人、成员、协作者、成员头像墙和团队负载；
- 不把个人工作台做成跨项目工作台；
- 不让搜索跨越所有项目的业务对象；
- 不在所有项目页展开完整任务、需求、风险和报告；
- 不使用四宫格统计墙或跨项目复杂趋势大屏；
- 不使用深色侧边栏、深色顶部栏或大面积黑色卡片；
- 不把用户头像改成黑色、深蓝色或渐变色；
- 不使用紫色 AI 发光、玻璃拟态、厚重阴影和 3D 图标；
- 不在产品界面出现“演示数据”“开发中”“占位”等开发痕迹。

## Product Architecture

### 范围规则

- 所有项目、站内消息、个人资料和系统设置属于全局范围；
- 个人工作台、需求、迭代、任务、风险、PM 助手、文件与知识、报告和项目设置属于当前项目范围；
- 站内消息可以汇总多个项目的提醒，但每条消息必须标明项目；
- 点击站内消息后自动切换对应项目并打开目标对象；
- Agent 生成需求、任务、风险和报告时先形成草稿，用户确认后再进入正式业务数据。

### 页面职责

| 页面 | 唯一主责任 | 主要展示 |
|---|---|---|
| 所有项目 | 找到项目并发现今日关注事项 | 项目列表、今日任务计数、逾期计数、重要风险计数、项目日历 |
| 个人工作台 | 推进当前项目今天的工作 | 当前项目全部任务范围、今日任务、进行中、逾期、阻塞、当前迭代和重点风险摘要 |
| 需求 | 定义当前项目要实现什么 | 需求状态、优先级、验收标准、关联迭代与任务 |
| 迭代 | 安排当前阶段要完成什么 | 迭代目标、起止日期、任务进度、燃尽与复盘 |
| 任务 | 跟踪具体执行单元 | 看板、列表、日期计划、任务详情与执行记录 |
| 风险 | 规划可能出现的问题 | 风险清单、概率、影响、等级、预防和应对方案 |
| PM 助手 | 基于当前项目分析与生成草稿 | 对话、引用、工具步骤、建议和人工确认 |
| 文件与知识 | 查找当前项目资料 | 文件目录、内容预览、来源、解析状态和上下文记录 |
| 报告 | 管理当前项目的结构化输出 | 报告列表、正文、证据、编辑、确认与发布 |
| 站内消息 | 处理跨项目短提醒 | 项目标记、事项摘要、时间、已读状态和跳转入口 |

## All Projects Page

### 页面目标

所有项目页只回答：用户有哪些项目，以及哪些项目今天需要关注。它不是跨项目数据大屏。

### 默认项目视图

页面结构：

1. 标题“所有项目”和一句简短说明；
2. 复用顶部栏搜索框搜索项目名称和描述，不在标题区增加第二个搜索框；
3. 复用顶部栏“新建项目”主按钮，不在内容区重复放置；
4. 标题区右侧放置“项目列表 / 日历视图”切换器；
5. 可选轻量提示：“今天有 3 个项目需要关注”；
6. 双列项目卡片或紧凑项目列表。

每个项目最多展示：

- 项目名称与状态；
- 当前迭代；
- 整体完成进度；
- 最近更新时间；
- 今日待完成任务数量；
- 逾期任务数量；
- 重要风险数量；
- 待确认 Agent 建议数量。

点击项目卡片后切换当前项目并进入个人工作台。

### 日历视图

点击“日历视图”后在当前主工作区原位切换，不打开新页面和大型模态框。日历顶部提供当前年月、上个月、下个月和“今天”。日期格使用任务、逾期、风险和里程碑图标表达当天事项。

### 悬停与跳转

鼠标悬停日期图标时显示旁侧提示框。内容按项目分组。点击具体事项时：

1. 将项目切换器更新为事项所属项目；
2. 更新当前项目上下文；
3. 进入任务、风险或迭代对应页面；
4. 定位并短暂高亮目标对象。

返回所有项目时保留原视图、月份和滚动位置。

## Interaction, Scrolling & Layering

- 左侧导航与顶部状态栏固定；
- 所有项目列表使用主内容区单一纵向滚动；
- 日历视图以主内容区为滚动容器，不嵌套多层纵向滚动；
- 项目切换下拉层、日历悬停提示和用户菜单位于普通内容之上；
- 抽屉和弹窗高于导航与提示框；
- 日历提示框离开图标或按 Esc 后关闭；
- 项目列表与日历切换使用 160–200ms 淡入和 4px 位移；
- Hover 使用 120–160ms 背景、边框与阴影过渡；
- 支持 `prefers-reduced-motion`，关闭位移动画但保留状态变化。

层级建议：普通内容 10、吸顶控件 20、导航与顶部栏 30、下拉和提示框 40、抽屉 50、模态确认 60、Toast 70。

## Stitch Generation Brief

将本 `DESIGN.md` 与已确认的个人工作台参考图同时提供给 Stitch。参考图是视觉基准，本文档是产品职责、配色边界与交互规则的基准。

本轮只生成三个 1440×1024 桌面画面：

1. 所有项目默认项目列表；
2. 所有项目月历视图；
3. 月历日期图标悬停并显示旁侧提示框的状态。

三个画面必须复用完全相同的侧边栏、顶部栏、项目切换器、头像、字体、图标、圆角和色彩。不要同时把项目列表、日历和悬停提示堆进一个画面。

优先检查：

- 所有项目是否位于个人工作台之前；
- 个人工作台是否明确属于当前项目；
- 项目切换器是否保持参考图的白底、浅边框和紧凑比例；
- 用户头像是否保持浅蓝配色；
- 黑色是否只用于 Logo、标题、重要文字和唯一主按钮；
- 所有项目页是否只展示项目摘要和今日关注事项；
- 页面是否没有负责人、成员、团队活动和跨项目复杂报表。
