# Java 模块个人开发者版开发需求说明

## 1. 背景

PM-Agent 当前已经具备用户认证、项目、任务和基础 Agent 对话入口，但如果将产品定位调整为“个人开发者使用”，Java 模块的建设重点需要从团队协作平台转向个人项目管理闭环。

个人开发者版的核心目标不是先完成复杂 RBAC、组织、多租户、审批和企业级通知，而是让一个开发者可以每天使用系统管理自己的项目、需求、任务、迭代、风险和报告，并让 Agent 基于真实业务数据进行分析、拆解、总结和风险提示。

本文档用于说明 Java 模块后续开发需求，面向产品设计、后端实现、前端联调和 Agent 能力规划。本文不是接口文档，文中的接口仅用于展示能力边界和模块入口，具体请求字段、响应字段、错误码和示例仍应在模块设计文档或接口规范中维护。

## 2. 目标

1. 补齐个人项目管理最小可用闭环：项目、需求、任务、迭代、风险、报告。
2. 强化任务和个人工作台能力，让系统具备日常使用价值。
3. 为 Agent 提供稳定、结构化、可追踪的业务数据和受控工具 API。
4. 降级团队协作复杂度，暂缓企业级 RBAC、多级审批、组织管理、通知中心和复杂审计。
5. 保持现有技术选型不变：Spring Boot 3、Sa-Token、MyBatis Plus、MySQL、Flyway、MapStruct、统一响应、统一异常和 traceId。

## 3. 定位与范围

### 3.1 目标用户

第一版优先面向个人开发者或单人项目管理者，典型使用场景包括：

- 管理个人产品、开源项目、外包项目、课程项目或实验性项目；
- 记录需求想法，并拆解为可执行任务；
- 规划短周期迭代或阶段目标；
- 跟踪任务状态、优先级、截止日期和完成情况；
- 记录风险、阻塞和复盘；
- 让 Agent 帮助查询项目状态、拆解需求、识别延期风险和生成报告草稿。

### 3.2 本期范围

| 模块 | 本期定位 | 说明 |
|---|---|---|
| 用户与认证 | 保留基础登录能力 | 继续使用 Sa-Token，个人版不扩展复杂账号体系 |
| 个人工作台 | 新增核心入口 | 汇总今日待办、逾期任务、进行中项目、近期风险 |
| 项目管理 | 强化个人项目概览 | 补充进度、统计、归档、项目概览 |
| 需求管理 | 新增轻量模块 | 记录“要做什么”，支持拆解任务 |
| 任务管理 | 重点强化 | 支持分页、排序、状态机、状态日志、逾期识别 |
| 迭代管理 | 新增轻量时间盒 | 管理本周、本月、版本或阶段 |
| 风险管理 | 新增手动闭环 | 支持风险登记、处理、关闭和事件记录 |
| 报告中心 | 新增草稿能力 | 支持周报、阶段报告草稿保存和人工编辑 |
| Agent 工具 API | 新增受控能力 | Java 提供业务查询和写入工具，Agent 不直接写库 |

### 3.3 暂不做范围

| 暂不做能力 | 原因 |
|---|---|
| 企业级 RBAC | 个人版只需要本人数据边界，复杂角色后置 |
| 多级审批流 | 与个人开发者日常使用不匹配 |
| 组织、部门、团队管理 | 不属于个人版核心闭环 |
| 复杂项目成员管理 | 仅保留项目 owner 和预留成员表 |
| 企业通知中心 | 站内消息、邮件、企微、钉钉后置 |
| 完整 RAG 知识库 | 按原规划第 6 阶段实现，本期只预留扩展点 |
| 复杂 BI 数据看板 | 本期只做项目和任务概览统计 |

## 4. 基础缺失部分

### 4.1 个人工作台

个人开发者每天进入系统后，需要先看到“今天该处理什么”。当前 Java 模块还没有工作台聚合接口，需要新增工作台服务，将项目、任务、风险和迭代信息整理为首页摘要。

核心能力：

- 今日待办：截止日期为今天或处于进行中状态的任务；
- 逾期任务：截止日期早于当前日期且未完成/未取消的任务；
- 进行中项目：状态为进行中、延期或暂停的项目；
- 当前迭代：当前日期落在起止日期内的迭代；
- 最近风险：待处理或处理中风险；
- 近期完成：最近完成的任务和关闭的风险；
- 快捷统计：项目数、待办数、逾期数、风险数。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/dashboard/overview` | 查询个人工作台总览 |
| `GET` | `/api/v1/dashboard/today` | 查询今日待办和逾期事项 |
| `GET` | `/api/v1/dashboard/recent-activities` | 查询近期项目活动 |

### 4.2 项目管理基础增强

当前项目模块已经支持创建、列表、详情、修改、状态修改和删除，但个人版还需要面向使用体验补齐概览和统计能力。

核心能力：

- 项目概览：基础信息、任务统计、需求统计、风险统计、当前迭代；
- 项目状态流转：未开始、进行中、暂停、延期、完成、归档；
- 项目归档：归档时记录归档原因和归档时间；
- 项目进度：根据任务完成情况计算，不要求用户手动填写；
- 项目编码唯一性：个人范围内避免重复项目编码；
- 项目删除保护：存在未完成任务或未关闭风险时给出明确提示。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/projects/{id}/overview` | 查询项目概览统计 |
| `PATCH` | `/api/v1/projects/{id}/archive` | 归档项目 |
| `GET` | `/api/v1/projects/{id}/activities` | 查询项目近期活动 |

### 4.3 任务管理基础增强

任务是个人开发者版最高频模块。当前任务模块已具备基础 CRUD 和状态修改，但还缺少分页、排序、状态机、日志查询和逾期识别。

核心能力：

- 任务列表分页：按项目、状态、优先级、截止日期、关键词过滤；
- 任务排序：按优先级、截止日期、更新时间排序；
- 状态流转规则：避免任意状态之间随意跳转；
- 状态日志查询：展示任务从创建到完成的过程；
- 逾期识别：按截止日期和状态计算是否逾期；
- 完成信息：记录完成时间、实际工时和完成说明；
- 任务快速创建：支持只填标题和项目，其他字段使用默认值；
- 任务复制：从已有任务复制标题、描述、优先级、预估工时。

建议任务状态流转：

```text
待处理 -> 开发中 -> 待联调 -> 待测试 -> 已完成
待处理 -> 已取消
开发中 -> 已取消
待联调 -> 开发中
待测试 -> 开发中
```

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/tasks` | 分页查询任务列表 |
| `GET` | `/api/v1/tasks/overdue` | 查询逾期任务 |
| `GET` | `/api/v1/tasks/{id}/status-logs` | 查询任务状态日志 |
| `PATCH` | `/api/v1/tasks/{id}/complete` | 完成任务 |
| `POST` | `/api/v1/tasks/{id}/copy` | 复制任务 |

### 4.4 需求管理最小闭环

个人开发者需要先记录“要实现什么”，再拆成任务。需求模块不需要复杂评审流程，但需要支撑需求记录、状态跟踪和任务关联。

核心能力：

- 创建需求：记录标题、描述、来源、优先级、状态；
- 需求列表：按项目、状态、优先级、关键词过滤；
- 需求详情：展示关联任务、进度、最近变更；
- 需求状态：草稿、已确认、开发中、已交付、已验收、已取消；
- 需求关联任务：一个需求可关联多个任务；
- 需求拆解入口：可由用户手动拆任务，也可由 Agent 生成任务草稿后人工确认。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/requirements` | 创建需求 |
| `GET` | `/api/v1/requirements` | 查询需求列表 |
| `GET` | `/api/v1/requirements/{id}` | 查询需求详情 |
| `PUT` | `/api/v1/requirements/{id}` | 修改需求 |
| `PATCH` | `/api/v1/requirements/{id}/status` | 修改需求状态 |
| `POST` | `/api/v1/requirements/{id}/tasks` | 为需求创建或关联任务 |

### 4.5 迭代管理最小闭环

个人版的迭代用于承载“本周计划”“v0.1 版本”“MVP 阶段”等时间盒。它不要求完整敏捷方法论配置，但需要帮助个人开发者聚焦当前周期。

核心能力：

- 创建迭代：名称、目标、起止日期、所属项目；
- 当前迭代：按日期识别正在进行的迭代；
- 迭代任务：将任务加入或移出迭代；
- 迭代进度：按任务完成情况计算；
- 迭代复盘：结束后填写复盘摘要；
- 迭代状态：未开始、进行中、已结束、已复盘。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/iterations` | 创建迭代 |
| `GET` | `/api/v1/iterations` | 查询迭代列表 |
| `GET` | `/api/v1/iterations/current` | 查询当前迭代 |
| `GET` | `/api/v1/iterations/{id}` | 查询迭代详情 |
| `POST` | `/api/v1/iterations/{id}/tasks` | 添加任务到迭代 |
| `DELETE` | `/api/v1/iterations/{id}/tasks/{taskId}` | 从迭代移除任务 |
| `PATCH` | `/api/v1/iterations/{id}/review` | 保存迭代复盘 |

### 4.6 风险管理最小闭环

个人开发者也需要记录风险和阻塞，例如延期、技术不确定、依赖不清晰、需求反复变化。第一版风险管理以手动登记和处理闭环为主。

核心能力：

- 创建风险：标题、描述、类别、等级、关联项目/任务；
- 风险列表：按项目、状态、等级过滤；
- 风险状态：草稿、已确认、处理中、已解决、已关闭、已拒绝；
- 风险事件：记录确认、处理、解决、关闭过程；
- 风险与任务关联：可以从任务生成风险，也可以让风险关联任务；
- 风险关闭：关闭时记录处理结论。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/risks` | 创建风险 |
| `GET` | `/api/v1/risks` | 查询风险列表 |
| `GET` | `/api/v1/risks/{id}` | 查询风险详情 |
| `PUT` | `/api/v1/risks/{id}` | 修改风险 |
| `PATCH` | `/api/v1/risks/{id}/status` | 修改风险状态 |
| `POST` | `/api/v1/risks/{id}/events` | 追加风险处理事件 |
| `PATCH` | `/api/v1/risks/{id}/close` | 关闭风险 |

### 4.7 报告中心最小能力

个人开发者版的报告不需要复杂报表平台，先支持周报和阶段报告草稿即可。报告可以由系统聚合数据生成，也可以由 Agent 起草，最终由用户人工编辑确认。

核心能力：

- 周报草稿：按项目和时间范围汇总完成任务、进行中任务、风险、下周计划；
- 阶段报告：按迭代或项目阶段汇总交付内容和问题；
- 报告保存：支持保存草稿、编辑、发布为已确认版本；
- 报告导出预留：先保存 Markdown 内容，后续再做 Word/PDF。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/reports/weekly-draft` | 生成周报草稿 |
| `GET` | `/api/v1/reports` | 查询报告列表 |
| `GET` | `/api/v1/reports/{id}` | 查询报告详情 |
| `PUT` | `/api/v1/reports/{id}` | 编辑报告内容 |
| `PATCH` | `/api/v1/reports/{id}/publish` | 确认报告 |

### 4.8 构建、测试与编码基线

在继续扩展业务前，需要先确保 Java 模块可稳定开发和验证。

基础要求：

- `mvn test` 可以稳定执行；
- 项目、任务、需求、迭代、风险核心 Service 必须有单元测试；
- Controller 至少覆盖统一响应、参数校验、登录态、幂等键；
- Flyway 迁移只新增不修改历史已应用脚本；
- 中文注释、中文错误提示、Markdown 文档必须保持 UTF-8；
- 新增业务错误码同步更新 `ErrorCode` 和 `docs/05-接口规范.md`；
- 写接口继续要求 `X-Idempotency-Key`，后续用 Caffeine 或 Redis 实现真实防重复执行。

## 5. 其他需要补充的能力

### 5.1 标签与快速筛选

个人开发者常按 `前端`、`后端`、`bug`、`重构`、`文档` 等方式组织任务。建议新增轻量标签能力，优先支持任务标签和需求标签。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/tags` | 查询标签列表 |
| `POST` | `/api/v1/tags` | 创建标签 |
| `POST` | `/api/v1/tasks/{id}/tags` | 为任务设置标签 |

### 5.2 搜索能力

个人项目数据积累后，需要跨项目搜索。第一版可以先基于 MySQL `like` 和索引字段实现，不引入 Elasticsearch。

搜索范围：

- 项目名称、项目编码、项目描述；
- 需求标题、需求描述；
- 任务标题、任务描述；
- 风险标题、风险描述；
- 报告标题和摘要。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/search` | 按关键词聚合搜索业务数据 |

### 5.3 备注与复盘

个人版需要低成本记录上下文。建议在项目、任务、迭代、风险上保留备注或复盘字段，不单独做复杂知识库。

建议规则：

- 备注内容使用 Markdown 文本；
- 备注不做全文版本管理；
- 迭代复盘和风险处理事件需要保留时间线；
- 大型文档和附件等到 RAG 阶段再引入。

### 5.4 导出与备份

个人工具需要让数据可带走。第一版可以从 Markdown/JSON 导出开始，避免过早做复杂 Word/PDF 模板。

接口展示：

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/projects/{id}/export` | 导出项目数据 |
| `GET` | `/api/v1/reports/{id}/export` | 导出报告 Markdown |

### 5.5 设置与偏好

个人版可以增加轻量偏好设置，提升日常使用效率。

建议能力：

- 默认项目；
- 默认任务视图；
- 默认排序方式；
- 工作台显示项配置；
- Agent 默认上下文项目。

## 6. Java 与 agent-service 协作边界

### 6.1 职责分工

| 层 | 职责 |
|---|---|
| Java 后端 | 业务数据、权限、幂等、状态日志、工具 API、报告草稿落库 |
| agent-service | Prompt 编排、模型调用、工具选择、流式输出、结构化结果生成 |
| 前端 | 对话展示、工具调用过程展示、人工确认动作卡片 |

关键原则：

1. Agent 不直接操作 Java 业务数据库；
2. Agent 生成的业务变更必须先成为草稿或建议；
3. 删除、状态修改、批量创建任务、创建风险等写动作必须由用户人工确认；
4. Java 调用 agent-service 时必须透传 `X-Trace-Id`、`X-User-Id`、`X-Tenant-Id`；
5. agent-service 调用 Java 工具 API 时必须携带 traceId 和幂等键。

### 6.2 Java 需要提供给 Agent 的工具能力

这些工具由 Java 提供或代理，供 agent-service 调用。

| 工具名 | Java 能力 | 说明 | 是否写操作 | 是否人工确认 |
|---|---|---|---|---|
| `query_dashboard_overview` | 查询个人工作台 | 获取当前待办、逾期、风险和项目摘要 | 否 | 否 |
| `query_project_overview` | 查询项目概览 | 获取项目进度、任务统计、风险统计 | 否 | 否 |
| `query_requirement_list` | 查询需求列表 | 支持需求拆解前获取上下文 | 否 | 否 |
| `query_task_list` | 查询任务列表 | 支持状态、优先级、截止日期过滤 | 否 | 否 |
| `query_overdue_tasks` | 查询逾期任务 | 支持风险分析和周报生成 | 否 | 否 |
| `query_iteration_overview` | 查询迭代概览 | 获取当前迭代目标、任务和进度 | 否 | 否 |
| `query_risk_list` | 查询风险列表 | 获取风险和处理状态 | 否 | 否 |
| `create_task_drafts` | 创建任务草稿 | 由需求拆解结果生成待确认任务草稿 | 是 | 是 |
| `create_risk_candidate` | 创建风险候选 | 由风险分析结果生成待确认风险 | 是 | 是 |
| `save_report_draft` | 保存报告草稿 | 保存 Agent 生成的周报或阶段报告 | 是 | 是 |

### 6.3 agent-service 需要提供给 Java 的接口

Java 模块要实现最终目的，需要 agent-service 至少提供以下能力接口。这里仍是能力展示，不是最终接口文档。

| 方法 | 路径 | 能力 | Java 使用场景 |
|---|---|---|---|
| `POST` | `/api/v1/agent/chat` | 普通 Agent 对话 | Java 转发前端对话请求，返回回答 |
| `POST` | `/api/v1/agent/chat/stream` | 流式 Agent 对话 | 前端需要逐步展示回答和工具调用状态 |
| `POST` | `/api/v1/agent/requirements/decompose` | 需求拆解 | 根据需求内容生成任务草稿列表 |
| `POST` | `/api/v1/agent/reports/weekly` | 周报草稿生成 | 根据项目、迭代、任务、风险生成周报 |
| `POST` | `/api/v1/agent/risks/analyze` | 风险分析 | 根据逾期任务、阻塞任务、迭代状态生成风险候选 |
| `POST` | `/api/v1/agent/projects/summary` | 项目摘要生成 | 将项目数据总结为自然语言摘要 |
| `POST` | `/api/v1/agent/tools/execute` | 工具调用编排 | agent-service 根据模型选择调用 Java 工具 |
| `GET` | `/api/v1/agent/traces/{traceId}` | 查询 Trace | Java 或前端展示 Agent 执行链路 |

### 6.4 agent-service 返回结果要求

agent-service 返回给 Java 的结构化结果需要满足以下要求：

| 能力 | 必须返回 |
|---|---|
| 对话 | `conversationId`、回答内容、工具调用摘要、token 用量、traceId |
| 需求拆解 | 任务草稿列表、优先级、预估工时、依赖说明、是否需要人工确认 |
| 周报生成 | Markdown 草稿、摘要、数据来源、风险提示、是否需要人工确认 |
| 风险分析 | 风险候选列表、等级、原因、建议处理动作、关联任务 |
| 项目摘要 | 当前状态、进展、阻塞、下一步建议 |
| 工具调用 | 工具名、入参摘要、出参摘要、状态、耗时、错误信息 |

通用要求：

- 输出语言为中文；
- 结构化字段必须通过 Pydantic 或 JSON Schema 校验；
- 信息不足时返回追问建议，不编造业务数据；
- 需要写业务时必须返回 `requiresConfirmation=true`；
- 所有响应必须包含 `traceId`、模型名、token 用量和耗时；
- 敏感字段必须脱敏后写入 Trace。

## 8. 验收标准

### 8.1 Java 基础能力验收

- 用户可以登录并访问个人项目数据；
- 用户可以查看个人工作台，看到今日待办、逾期任务、当前项目和风险；
- 用户可以创建项目，并查看项目概览统计；
- 用户可以创建需求，并将需求拆解或关联到任务；
- 用户可以创建任务、更新任务、按合法状态流转任务；
- 每次任务状态变化都会写入状态日志；
- 用户可以创建迭代、加入任务、查看迭代进度和保存复盘；
- 用户可以创建风险、追加处理事件并关闭风险；
- 用户可以生成和保存报告草稿；
- 核心列表支持分页、排序和过滤；
- 后端统一响应、错误码、traceId、幂等键规则保持一致。

### 8.2 Agent 协作验收

- Java 可以调用 agent-service 完成普通对话；
- Java 可以调用 agent-service 获取需求拆解结果；
- Java 可以调用 agent-service 获取周报草稿；
- Java 可以调用 agent-service 获取风险分析候选；
- agent-service 不直接操作业务数据库；
- Agent 写业务必须先生成草稿或候选，并等待人工确认；
- traceId 可以贯穿前端、Java、agent-service 和模型调用；
- Agent 工具调用失败时，Java 能拿到明确错误并返回统一响应。

## 9. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 个人版范围继续膨胀 | 严格先做个人工作台、项目、需求、任务、迭代、风险、报告闭环 |
| 过早做企业协作 | RBAC、组织、复杂成员、审批和通知全部后置 |
| Agent 输出不可控 | Java 只接受结构化草稿和候选，写业务必须人工确认 |
| 数据模型变更频繁 | 需求、迭代、风险先按最小字段落地，后续只增字段 |
| 搜索和导出复杂化 | 先用 MySQL 查询和 Markdown/JSON 导出，不提前引入新中间件 |
| 测试欠账扩大 | 每新增一个模块同步补 Service 和 Controller 核心测试 |
