# 模块设计：用户与认证

## 背景

用户与认证模块是 PM-Agent 第 1 阶段业务闭环的入口。当前后端已完成 Spring Boot 基础配置、Sa-Token JWT 登录态、MyBatis Plus 数据访问、Flyway 初始化数据和统一响应结构，用户可以通过注册或登录获得访问系统的登录态，并查询当前账户信息。

## 模块职责

用户与认证模块负责：

- 用户注册；
- 用户登录；
- 用户登出；
- 查询当前登录账户信息；
- 维护用户密码哈希、启用状态和最近登录时间。

本模块不负责：

- RBAC 角色权限；
- 项目成员权限判断；
- 登录日志与完整审计日志；
- Redis 会话集中存储；
- 第三方 OAuth 登录。

## 涉及术语

| 术语 | 说明 |
|---|---|
| 登录态 | 用户通过 Sa-Token JWT 获得的访问凭证 |
| 当前用户 | 当前请求中由 `Authorization` 解析出的登录用户 |
| 幂等键 | 写接口请求头 `X-Idempotency-Key`，用于防重复提交 |
| 用户状态 | `enabled` 表示启用，`disabled` 表示禁用 |

## 业务流程

### 注册流程

```text
前端提交注册表单
  ↓
POST /api/v1/auth/register
  ↓
后端校验用户名、密码、展示名等参数
  ↓
用户名 trim 并转小写
  ↓
使用 BCrypt 生成密码哈希
  ↓
写入 pm_user
  ↓
Sa-Token 建立登录态
  ↓
返回 token 与安全用户资料
```

### 登录流程

```text
前端提交用户名和密码
  ↓
POST /api/v1/auth/login
  ↓
后端按用户名查询 enabled / 未删除用户
  ↓
BCrypt 校验密码
  ↓
Sa-Token 建立登录态
  ↓
更新 last_login_at
  ↓
返回 token 与安全用户资料
```

### 当前用户流程

```text
前端携带 Authorization: Bearer <token>
  ↓
GET /api/v1/users/me
  ↓
@SaCheckLogin 校验登录态
  ↓
CurrentUserHolder 读取当前用户 ID
  ↓
查询 pm_user
  ↓
返回安全用户资料
```

## 数据模型

当前复用第 1 阶段 `pm_user` 表。

| 字段 | 说明 |
|---|---|
| `username` | 登录用户名，应用层统一转小写 |
| `password_hash` | BCrypt 密码哈希，不对外返回 |
| `display_name` | 展示名称 |
| `email` | 邮箱，可空 |
| `mobile` | 手机号，可空 |
| `status` | 用户状态，当前支持 `enabled` / `disabled` |
| `last_login_at` | 最近登录时间 |
| `tenant_id` | 第 1 阶段固定为 `0` |
| `deleted` | 逻辑删除标记 |

用户名唯一性由数据库索引 `uk_user_username(tenant_id, username, deleted)` 兜底。

## 接口清单

| 方法 | 路径 | 说明 | 权限 | 幂等键 |
|---|---|---|---|---|
| `POST` | `/api/v1/auth/register` | 注册新用户并返回登录态 | 匿名 | 必填 |
| `POST` | `/api/v1/auth/login` | 用户登录 | 匿名 | 必填 |
| `POST` | `/api/v1/auth/logout` | 当前用户登出 | 登录用户 | 必填 |
| `GET` | `/api/v1/users/me` | 查询当前账户信息 | 登录用户 | 不需要 |

## 请求 / 响应 DTO

### 注册请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名，最长 64 个字符 |
| `password` | string | 是 | 密码，8 到 64 个字符 |
| `displayName` | string | 是 | 展示名称 |
| `email` | string | 否 | 邮箱 |
| `mobile` | string | 否 | 手机号 |

### 登录请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码 |

### 登录响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `tokenName` | string | token 请求头名称，当前为 `Authorization` |
| `tokenValue` | string | JWT token 值 |
| `user` | object | 当前用户安全资料 |

### 当前用户响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 用户 ID |
| `tenantId` | number | 租户 ID，第 1 阶段为 `0` |
| `username` | string | 用户名 |
| `displayName` | string | 展示名称 |
| `email` | string | 邮箱 |
| `mobile` | string | 手机号 |
| `status` | string | 用户状态 |
| `lastLoginAt` | string | 最近登录时间 |

响应中不返回 `passwordHash`。

## 前端页面

当前前端已有登录页与本地 Mock 能力。后续联调时，登录页可从 Mock 切换到：

- `POST /api/v1/auth/login`；
- `GET /api/v1/users/me`。

注册入口是否在第 1 阶段页面开放，可按前端开发节奏决定。

## Agent 介入点

第 1 阶段无 Agent 介入。后续 Agent 工具调用业务接口时，必须以用户身份执行，并携带 `Authorization`、`X-Trace-Id` 与 `X-Idempotency-Key`。

## 权限与风险

| 风险 | 当前处理 |
|---|---|
| 密码明文泄露 | 使用 BCrypt 哈希，接口和日志不返回密码或 token |
| 用户枚举 | 登录失败统一返回“用户名或密码错误” |
| 重复注册 | 应用层查询 + 数据库唯一索引兜底 |
| 未登录访问 | 使用 `@SaCheckLogin` 与全局异常处理 |
| 登出强失效 | 第 1 阶段执行 Sa-Token logout，Redis 阶段再增强集中会话能力 |

## 开发步骤

已完成：

1. 补齐 Mapper 扫描、MyBatis Plus 自动填充、Sa-Token JWT、OpenAPI 配置；
2. 新增 `auth` 与 `user` 后端模块；
3. 实现注册、登录、登出、当前用户接口；
4. 前端登录页接入真实接口；
5. 增加基础单元测试和 Controller 测试。

后续按需补充：

- Redis 引入后的 JWT 黑名单或集中会话失效策略；
- 第 2 阶段引入 RBAC 后，扩展角色与权限校验。

## 验收标准

- `mvn -f backend/pom.xml test` 通过；
- `POST /api/v1/auth/register` 可注册用户并返回 token；
- `POST /api/v1/auth/login` 可登录并返回 token；
- `GET /api/v1/users/me` 携带 token 时返回当前用户资料；
- `POST /api/v1/auth/logout` 可登出；
- 写接口缺少 `X-Idempotency-Key` 时返回 `10002`；
- 错误密码返回 `20004 用户名或密码错误`；
- 响应不包含密码哈希；
- 日志不打印密码、密码哈希或 token。
