# 模块设计：用户与认证

## 1. 背景

Java 后端支持多个用户注册和登录，但不提供租户、组织或租户隔离。邮箱是唯一登录标识，用户名用于用户资料展示和识别。

## 2. 模块职责

负责：

- 用户注册；
- 邮箱密码登录；
- 退出登录；
- 查询和修改当前用户的用户名、邮箱；
- 修改当前用户密码；
- 更新最近登录时间。

不负责：

- 多租户、组织和租户隔离；
- RBAC、用户列表管理和用户删除；
- 展示名称和手机号；
- 第三方登录；
- 项目、任务、Agent 和文件业务。

## 3. 业务流程

### 3.1 注册

```text
提交用户名、邮箱和密码
  -> 规范化用户名和邮箱
  -> 检查用户名、邮箱是否已存在
  -> 生成 BCrypt 密码哈希
  -> 写入 pm_user
  -> Sa-Token 建立登录态
  -> 返回 token 和安全用户资料
```

数据库唯一索引负责处理并发注册产生的最终冲突。

### 3.2 登录

```text
提交邮箱和密码
  -> 规范化邮箱
  -> 按邮箱查询用户
  -> BCrypt 校验密码
  -> 校验用户状态
  -> Sa-Token 建立登录态并写入 Redis
  -> 更新 last_login_at
  -> 返回 token 和安全用户资料
```

邮箱不存在和密码错误统一返回 `20004`，避免暴露邮箱是否已注册。

### 3.3 当前用户

受保护接口通过 `@SaCheckLogin` 校验登录态，再通过 `CurrentUserHolder` 取得用户 ID。响应不包含密码哈希。

Sa-Token 使用 Redis 持久化登录会话，Spring Boot 重启后仍可读取未过期且未退出的登录态。JWT 有效期由 `sa-token.timeout` 统一控制，Sa-Token 内部 Redis 键名由框架维护。

## 4. 数据模型

本模块只使用 `pm_user`，包含：

- `id`
- `username`
- `email`
- `password_hash`
- `status`
- `last_login_at`
- `created_at`
- `updated_at`

详细约束见 [04-数据模型.md](./04-数据模型.md)。

## 5. 接口设计

### 5.1 注册用户

- 方法：`POST`
- 路径：`/api/v1/auth/register`
- 权限：匿名

```json
{
  "username": "dev_user",
  "email": "dev@example.com",
  "password": "Dev123456"
}
```

错误码：`10001`、`10003`、`20006`、`20008`。

### 5.2 邮箱登录

- 方法：`POST`
- 路径：`/api/v1/auth/login`
- 权限：匿名

```json
{
  "email": "dev@example.com",
  "password": "Dev123456"
}
```

登录数据：

```json
{
  "tokenName": "Authorization",
  "tokenValue": "JWT_TOKEN",
  "user": {
    "id": 1,
    "username": "dev_user",
    "email": "dev@example.com",
    "status": "enabled",
    "lastLoginAt": "2026-07-12T17:00:00"
  }
}
```

错误码：`20004`、`20005`。

### 5.3 退出登录

- 方法：`POST`
- 路径：`/api/v1/auth/logout`
- 权限：登录用户

### 5.4 查询当前用户

- 方法：`GET`
- 路径：`/api/v1/users/me`
- 权限：登录用户

### 5.5 修改当前用户资料

- 方法：`PUT`
- 路径：`/api/v1/users/me`
- 权限：登录用户

```json
{
  "username": "new_name",
  "email": "new@example.com"
}
```

用户名和邮箱均必填；修改邮箱后，下一次登录使用新邮箱。

### 5.6 修改密码

- 方法：`PUT`
- 路径：`/api/v1/users/me/password`
- 权限：登录用户

```json
{
  "oldPassword": "Old123456",
  "newPassword": "New123456",
  "confirmPassword": "New123456"
}
```

错误码：`10001`、`20007`。

## 6. 实现结构

```text
com.ning.pm
├── auth
│   ├── controller
│   ├── dto
│   └── service
├── infrastructure
│   └── redis
│       └── RedisKeyDefinition.java
└── user
    ├── controller
    ├── converter
    ├── domain
    ├── dto
    ├── repository
    └── service
```

Controller 和 ServiceImpl 使用 Lombok `@RequiredArgsConstructor`；Controller 和异常处理器使用 `@Slf4j`。

## 7. 日志与安全

- Controller 记录操作开始和成功；
- 登录和注册日志不输出邮箱、密码或 token；
- 用户资料日志只记录 userId；
- 系统异常由全局异常处理器记录堆栈；
- 密码只保存 BCrypt 哈希。

## 8. 验收标准

- 可以注册多个邮箱不同的用户；
- 重复用户名返回 `20006`；
- 重复邮箱返回 `20008`；
- 登录只接受邮箱和密码；
- 禁用用户不能登录；
- 用户资料可以修改用户名和邮箱；
- 后端重启后，未过期且未退出的 Token 仍可访问受保护接口；
- 退出登录后，对应 Token 在 Redis 中失效；
- 响应不包含 `passwordHash`、`displayName`、`mobile` 或 `tenantId`；
- 日志不包含密码、哈希、邮箱和 token。
