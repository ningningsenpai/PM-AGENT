# 索引初始化与重建流程改造说明

## 改造结果

项目索引已经从 Java/Python 往返链路收敛为 Python 进程内编排。

```text
前端提交完整目录清单，后端生成同步计划
  ↓
前端根据计划复用单文件更新接口
  ↓
Python 先落库、事务外写 MinIO
  ↓
前端调用 /files/parse/init
  ↓
Python 读取对象、解析、调用模型
  ↓
Pydantic 校验
  ↓
写 file_details、更新数据库投影
  ↓
按本轮成功 Detail 的 file_id 增量更新五个规则分区
  ↓
从 project_facts 增量更新 long_term_memory.json
  ↓
从数据库完整生成 index.json
```

已删除的旧链路：

- Java 组装文件分析 DTO；
- Java 生成临时 URL；
- Python 通过 HTTP 下载；
- Python 同步返回 Java；
- Java 回填数据库；
- Java 下载旧索引后读改写。

## 验收要点

- 不存在 `/api/v1/project-files/analyze`；
- MinIO 与 LLM 调用不处于数据库事务中；
- `index.json` 可从 MySQL 重新生成；
- `project_specification.json` 只保存五个规则分区的路径、哈希和条目数，不保存 `development_stage`；
- 规则分区只接收取得来源资格的成功 Detail 中对应类别的结构化候选，并按 `file_id` 完整替换自身分组；
- `project_facts` 继续增量更新 `long_term_memory.json`，不再参与规则生成；
- 文件内容变化时，旧分析结果无法通过条件更新覆盖新版本；
- 项目规范先于索引发布，解析接口能区分完整成功与部分成功；
- `eval`、`training` 等受保护目录不受影响。
