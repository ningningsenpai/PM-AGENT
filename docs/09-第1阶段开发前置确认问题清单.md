# 第 1 阶段开发前置确认问题清单

## 1. 背景

当前 PM-Agent 已完成项目定位、技术选型、业务流程、数据模型、接口规范、Agent 设计、成本控制以及项目级 Skill 的整理。第 1 阶段即将进入工程初始化与编码阶段。

在正式执行 `backend/`、`frontend/`、`deploy/` 等工程骨架初始化前，需要先确认若干会影响目录结构、依赖版本、数据库迁移、本地运行方式和分支策略的问题。

本文档仅用于收集开发前置决策。用户回答完成后，再按确认结果执行工程初始化与第 1 阶段开发。

---

## 2. 目标

1. 将第 1 阶段开工前的问题集中到一个文档中，避免边做边改基础决策；
2. 明确每个问题的影响范围、可选方案和推荐方案；
3. 区分“必须回答后才能开工”和“可使用默认值后续再调整”的问题；
4. 作为后续工程初始化、脚手架生成、配置文件编写的依据。

### Q6：第 1 阶段采用什么分支策略？

当前项目采用单仓库 Monorepo，目录用于区分模块，分支用于区分任务。早期 `frontend` 分支不再作为长期模块分支使用，可视为前端初始化任务分支；后续后端工程从 `main` 新建任务分支初始化。

| 项目 | 内容 |
|---|---|
| 影响范围 | 后端代码提交位置、分支命名、后续合并策略、README 表述 |
| 可选方案 A | 使用长期 `frontend` / `backend` 分支分别维护模块 |
| 可选方案 B | 使用单仓库 Monorepo，`main` 作为完整项目基线，`feature/*` 表示任务分支 |
| 推荐方案 | 方案 B |
| 推荐理由 | 目录已经能表达模块边界，分支更适合表达开发任务；可减少文档、部署配置和联调代码在长期模块分支间反复同步 |

确认结果：采用方案 B。当前 `frontend` 分支按 `feature/init-frontend` 任务分支语义处理；后续后端初始化使用 `feature/init-backend`，不再新增长期 `backend` 分支。

```text
Q6：单仓库 Monorepo + main 主干 + feature/* 任务分支
```

## 8. 回答后的执行顺序

用户确认上述问题后，建议按以下顺序执行。

### 8.1 工程初始化

1. 根据 Q6 从 `main` 创建或整理当前 `feature/*` 任务分支；
2. 根据 Q1 初始化 `backend/` Spring Boot 3 工程；
3. 根据 Q3、Q4 初始化 `frontend/` Vue 3 工程；
4. 根据 Q5、Q8、Q9 初始化本地开发配置与部署说明。

### 8.2 后端基础能力

1. 配置 MyBatis Plus、Sa-Token、Knife4j；
2. 实现统一响应 `R<T>`；
3. 实现错误码与异常体系；
4. 实现全局异常处理；
5. 实现 traceId 拦截器；
6. 实现幂等键拦截器，第 1 阶段使用本地缓存；
7. 根据 Q2、Q7 创建数据库迁移脚本。

### 8.3 第 1 阶段业务闭环

1. 实现登录和当前用户接口；
2. 实现项目创建、列表、详情接口；
3. 实现任务创建、列表、状态流转接口；
4. 实现登录页、主布局、项目列表页、项目详情页、任务看板页；
5. 完成手动验收。
