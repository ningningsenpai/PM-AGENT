# 项目文件可靠上传模块设计

## 1. 目标

Java后端统一负责项目文件元信息、MinIO对象写入和访问控制。文件按“用户—项目—business—文件”组织，内容更新覆盖原对象，不保存历史版本。

## 2. 范围

- 单文件最大50MB；
- `project/user/system`三个business命名空间；
- 文件上传、内容覆盖、逻辑路径修改、列表、只读地址和删除；
- 快速指纹和内容SHA-256两级判断；
- 上传批次及明细用于幂等拦截、状态记录和失败修复；
- 不引入RabbitMQ、outbox、Redis、文件分片和文件历史版本。

## 3. 路径规则

逻辑路径保存在MySQL，例如：

```text
backend/src/main/java/com/ning/pm/auth/AuthController.java
```

MinIO对象键创建后保持不变：

```text
PM-AGENT/{ownerUserId}/{projectId}/{businessCode}/{fileId}
```

修改文件名或目录只更新`relative_path`，不移动MinIO对象。修改内容使用同一`object_key`覆盖写。MinIO桶必须关闭对象版本控制。

## 4. 变更判断

快速指纹不读取内容：

```text
SHA-256(normalizedRelativePath + sizeBytes + sourceMtimeMs)
```

`content_hash`对完整内容计算SHA-256。

| 条件 | 动作 |
|---|---|
| 快速指纹和内容哈希均相同 | 跳过MinIO写入 |
| 快速指纹不同、内容哈希相同 | 只更新元信息 |
| 路径变化、内容哈希相同 | 只更新逻辑路径 |
| 内容哈希不同 | 覆盖原MinIO对象 |

`upload_failed`和`verify_required`状态再次提交内容时必须强制覆盖，不能只凭相同哈希跳过。

## 5. 状态与枚举

所有有限取值字段在Java中使用枚举，数据库保存枚举编码字符串：

- `UserStatus`；
- `ProjectStatus`；
- `FileBusinessType`；
- `ProjectFileStatus`；
- `FileUploadStatus`；
- `FileUploadItemStatus`；
- `FileChangeAction`；
- `FileUploadSource`。

内容覆盖先将文件从`active`抢占为`updating`。MinIO结果不确定时进入`verify_required`，上传明细保留新内容的哈希、大小、类型和源修改时间，供再次覆盖修复。

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/projects` | 创建最小项目文件空间 |
| `GET` | `/api/v1/projects` | 查询当前用户项目 |
| `POST` | `/api/v1/projects/{projectId}/files` | 上传单个文件 |
| `PUT` | `/api/v1/projects/{projectId}/files/{fileId}/content` | 覆盖文件内容 |
| `PATCH` | `/api/v1/projects/{projectId}/files/{fileId}/path` | 修改逻辑路径 |
| `GET` | `/api/v1/projects/{projectId}/files` | 查询文件列表 |
| `GET` | `/api/v1/projects/{projectId}/files/{fileId}/read-url` | 获取五分钟只读地址 |
| `DELETE` | `/api/v1/projects/{projectId}/files/{fileId}` | 删除文件和对象 |

上传和覆盖接口必须传`X-Idempotency-Key`。覆盖、路径修改和删除必须传当前`lockVersion`。

## 7. 一致性边界

MinIO调用不放入数据库事务。文件状态和乐观锁负责阻止并发覆盖：

1. MySQL抢占文件状态；
2. 对稳定对象键执行MinIO覆盖；
3. 更新文件当前元信息；
4. 失败或结果不确定时保留上传明细并进入待校验状态。

直接覆盖意味着旧内容不可恢复，这是当前方案明确接受的取舍。

## 8. 验收标准

- 同一文件多次内容更新的`object_key`保持不变；
- 项目内路径修改不调用MinIO写入或删除；
- 内容哈希相同时不覆盖对象；
- 内容哈希变化时覆盖原对象且不产生版本表；
- 并发请求中只有匹配`lockVersion`的请求可以抢占；
- 非所属用户不能查询或修改项目文件；
- 所有响应使用`R<T>`并包含`traceId`；
- Controller记录上传、覆盖、路径修改、查询和删除日志。
