# 00 术语表

本文档定义 PM-Agent 智能项目管理 Agent 平台的统一产品术语。所有文档、数据库表、Java 类、前端页面、API 路径和 Agent Prompt 均应优先使用本文档中的标准术语。

---

## 1. 使用规则

1. 新增业务概念前，先检查本文档是否已有对应术语；
2. 确需新增术语时，先更新本文档，再进入数据建模、接口设计和前端实现；
3. 代码命名使用“英文标识”，页面与文档使用“标准术语”；
4. “禁用同义词”不是说 Agent 不能识别，而是指系统输出、表名、类名、接口路径中不使用；
5. Agent 可以识别同义词，但对用户输出时必须回到标准术语。

---

## 2. 核心业务术语

| 标准术语 | 英文标识 | 一句话定义 | 范围边界 | 禁用同义词 | 关联术语 |
|---|---|---|---|---|---|
| 项目 | project | 一个独立交付目标，包含需求、任务、迭代、风险和报告 | 第一版按个人项目管理设计，后续支持团队协作 | 工程、计划、项目集 | 用户、需求、任务、迭代、风险 |
| 项目成员 | project_member | 参与某个项目的用户及其项目内角色 | 区别于系统全局用户角色 | 成员关系、参与人 | 项目、用户、角色 |
| 用户 | user | 使用唯一邮箱登录系统并维护本人资料的人 | 当前 Java 基座支持多个用户，但不提供租户隔离 | 账号、成员（除非指项目成员） | 登录态、邮箱 |
| 角色 | role | 一组权限的集合 | 第 2 阶段引入 RBAC 后正式生效 | 身份、岗位 | 用户、权限 |
| 权限 | permission | 对某类资源或动作的访问控制 | 通过 Sa-Token 注解校验 | 权限点、功能点 | 角色、用户 |
| 需求 | requirement | 从用户或业务视角描述“要实现什么”的诉求 | 已确认后可拆解为任务 | Story、用户故事、功能点 | 项目、任务、Agent |
| 任务 | task | 可分配、可执行、可跟踪状态的最小工作单元 | 必须归属于项目，可关联需求和迭代 | TODO、工作项 | 项目、需求、迭代、风险 |
| 任务依赖 | task_dependency | 一个任务对另一个任务的前置依赖关系 | 用于阻塞识别和风险分析 | 前置任务关系 | 任务、风险 |
| 迭代 | iteration | 项目内一段有起止时间的工作周期，统一承载敏捷 Sprint 和瀑布阶段 | 表名、类名、API 使用 `iteration`；Sprint/阶段只作为同义词 | Sprint（代码中禁用）、阶段（代码中禁用）、轮次 | 项目、任务、报告 |
| 风险 | risk | 可能影响项目交付的不确定因素 | 风险是“可能发生”，问题是“已经发生” | 隐患、风险点 | 项目、任务、Agent |
| 问题 | issue | 已经发生并影响进度、质量或交付的事项 | 与风险区分；问题可由风险演变而来 | bug（除非特指缺陷）、异常 | 风险、任务 |
| 报告 | report | 项目周报、迭代报告、风险报告等结构化输出 | 第一版以周报草稿为主 | 周报（周报是报告子类） | 项目、迭代、Agent |
| 站内消息 | notification | 系统内发送给用户的提醒 | 第一版只做站内消息，邮件/企微/钉钉后置 | 通知（泛称可用） | 用户、任务、风险 |
| 项目文件 | project_file | 用户为项目选择并由 Java 保存到对象存储的源码、文档或其他资料 | 使用项目根目录内相对路径标识，不保存用户本机绝对路径 | 代码包、项目附件（泛称） | 项目、单文件上传 |
| 单文件上传 | single_file_upload | 前端校验一个文件后调用一次 Java 上传接口的过程 | Java 先落库，再单次写 MinIO；当前流程不自动重试 | 批次上传、文件包上传 | 项目文件、文件上传结果 |
| 文件上传结果 | file_upload_result | Java 对单个文件返回的成功或失败结果 | 前端只汇总结果；失败文件由后续更新项目业务处理 | 批次结果 | 单文件上传、项目更新 |
| 项目更新 | project_update | 对已有项目资料和失败文件进行后续补充或修正的业务入口 | 当前单文件首次上传只提示进入该业务，不实现自动重试 | 上传重试轮次 | 项目、项目文件 |

## 3. Agent 相关术语

| 标准术语 | 英文标识 | 一句话定义 | 范围边界 | 禁用同义词 | 关联术语 |
|---|---|---|---|---|---|
| Agent | agent | 具备推理、工具选择和结果总结能力的智能执行者 | 不等同于底层大模型；不能直接操作数据库 | 助手（UI 可用“Agent 助手”）、机器人、模型 | 工具、Trace、模型 |
| 模型 | model | Agent 调用的大语言模型 | 如 DeepSeek、Claude、GPT | Agent | Agent、模型路由 |
| 模型路由 | model_router | 按任务选择不同模型的策略或组件 | 第一版默认 DeepSeek，后续扩展其他 Provider | 模型切换 | 模型、成本控制 |
| 工具 | tool | Agent 可调用的受控业务能力 API | 由 Java 后端提供或代理；必须有 schema | function、接口（接口是实现形式） | Agent、Trace |
| 工具调用 | tool_call | Agent 调用某个工具的一次执行记录 | 需要记录入参、出参、耗时、错误 | function call | 工具、Trace |
| Trace | trace | Agent 单次决策链路的完整追踪记录 | 与业务审计日志不同，Agent Trace 第 3 阶段必须落地 | 日志、记录 | Agent、工具调用 |
| Prompt | prompt | 给模型的指令、上下文和输出格式约束 | Prompt 模板需要编号或命名 | 提示词（可解释用） | Agent、模型 |
| RAG | rag | 基于文档检索增强模型回答的能力 | 第 6 阶段引入，不提前完整实现 | 知识库问答（是业务表现） | 文档、向量检索 |
| 人工确认 | human_confirmation | 高风险 Agent 动作执行前由用户确认 | 不是完整审批流，不包含多级审批 | 审批（第一版禁用） | Agent、工具、风险 |

## 4. 状态与流程术语

| 标准术语 | 英文标识 | 一句话定义 | 范围边界 | 禁用同义词 | 关联术语 |
|---|---|---|---|---|---|
| 状态流转 | status_transition | 业务对象从一个状态变为另一个状态 | 第一版只做状态流转，不做完整审批流 | 审批流 | 任务、风险、需求 |
| 审批流 | approval_workflow | 状态变更前需多人审批的流程 | 第一版不做，企业级阶段再考虑 | BPM（不是同义但同类重型能力） | 人工确认 |
| 状态日志 | status_log | 记录业务状态变化的日志 | 与审计日志不同，服务于流程复盘 | 审计日志 | 状态流转 |
| 审计日志 | audit_log | 记录谁在何时对什么资源做了什么关键操作 | 第 7 阶段或更早增强；第 1 阶段仅留注解占位 | 普通日志 | 权限、合规 |
| 链路追踪 | trace_id | 一次请求跨前端、Java、Python、LLM 的统一追踪标识 | 响应必须返回 `traceId` | requestId（可作为技术同义） | 日志、Agent Trace |
