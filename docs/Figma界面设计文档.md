# Figma 界面设计文档

## 1. 背景

本文档用于指导 PM-Agent 第一阶段前端界面设计稿的构建，重点解决以下问题：

1. 明确第一阶段需要在 Figma 中呈现的页面范围；
2. 明确每个页面承载的核心功能、信息结构和接口承接关系；
3. 统一页面拆分方式，避免设计稿继续停留在“单个后台页面 + 若干占位卡片”的状态；
4. 为后续 Vue 3 + Naive UI 前端实现提供页面级参考。

当前第一阶段的界面设计目标不是只展示登录、项目列表和任务看板，而是要把 PM-Agent 作为一个完整的智能项目管理产品进行表达。即使部分 AI 能力、RAG 能力和自动扫描能力在后端尚未完全实现，也需要在第一阶段设计稿中保留正式页面入口和禁用态，以便后续阶段平滑接入。

---

## 2. 文档定位与使用规则

### 2.1 文档定位

本文档是 PM-Agent 第一阶段 Figma 设计稿的页面级设计文档，主要服务于：

- Figma 页面原型拆分；
- 页面信息架构设计；
- 页面功能展示与禁用态设计；
- 前端页面与后端接口的映射；
- 后续前端实现时的页面级参考。

### 2.2 编写顺序

每个页面按照以下顺序描述：

```text
界面 → 接口 → 功能
```

含义如下：

| 维度 | 说明 |
|---|---|
| 界面 | 页面布局、主要区域、关键模块、交互状态 |
| 接口 | 页面需要承接的后端接口或后续待补接口 |
| 功能 | 用户在该页面可以完成的业务动作 |

### 2.3 设计稿约束

1. 设计稿应是正式产品页面，不放置设计说明、开发备忘或思考过程；
2. 可在页面内展示禁用态、空状态、加载态、错误态和后续启用提示；
3. 第一阶段面向个人开发者 / 单人项目管理者，不展示复杂租户、组织和企业级审批；
4. AI 相关页面需要出现入口并可进入页面，但核心执行按钮置灰，显示“后续阶段启用”；
5. 代码上传能力作为第一阶段项目管理页的重要功能展示，设计稿需画出压缩包 / 文件夹上传流程。

## 3. 第一阶段设计范围

### 3.1 目标用户

第一阶段优先服务：

- 个人开发者；
- 单人项目管理者；
- 小型项目的负责人。

第一阶段暂不重点服务：

- 大型组织管理员；
- 多租户 SaaS 管理员；
- 复杂企业审批流程中的多角色用户。

### 3.2 页面范围

第一阶段 Figma 设计稿需要包含以下页面：

| 页面 | 定位 | 第一阶段设计要求 |
|---|---|---|
| 项目介绍页 | 产品公开入口 | 必须完整设计 |
| 登录页 | 用户进入系统入口 | 必须完整设计 |
| 注册页 | 新用户创建账号入口 | 必须完整设计 |
| 项目总览页 | 登录后的全局项目状态首页 | 必须完整设计 |
| 项目管理页 | 项目列表、切换项目、新建项目、代码上传、任务入口 | 必须完整设计 |
| 项目详情页 | 单个项目的基础信息、任务、风险、代码资料入口 | 必须完整设计 |
| 风险中心页 | AI 风险分析入口与风险结果承载页 | 页面完整展示，AI 扫描按钮禁用 |
| 任务看板页 | 任务状态、进度、风险处理情况展示 | 必须完整设计 |
| PM 助手页 | 人机对话、项目分析、报告生成入口 | 页面完整展示，核心 AI 操作禁用 |
| 报告中心页 | 报告、上传资料、后续 RAG 资料管理入口 | 页面完整展示，资料解析 / RAG 操作禁用 |
| 系统设置页 | 本地设置、版本、存储位置、功能开关 | 必须完整设计 |
| 用户中心页 | 用户资料查看与基础修改 | 必须完整设计 |

### 3.3 第一阶段实现分层

虽然以上页面都需要进入第一阶段设计稿，但在界面中需要通过状态区分实现程度：

| 类型 | 说明 | 页面表现 |
|---|---|---|
| 已可实现能力 | 后端接口已规划或已存在 | 正常按钮、正常表单、正常列表 |
| 待补接口能力 | 第一阶段需要实现，但接口尚未补齐 | 正常展示流程，并在文档标注“待补接口” |
| AI 后续启用能力 | 页面需要出现，但后端 AI 能力未启用 | 页面可进入，核心按钮置灰，展示启用说明 |
| 后续增强能力 | 当前只用于表达产品方向 | 以空状态、标签或只读卡片展示 |

## 4. 总体信息架构

### 4.1 公开页面

```text
项目介绍页
  ├── 登录页
  └── 注册页
```

### 4.2 登录后主导航

```text
主布局
├── 项目总览
├── 项目管理
│   ├── 项目列表
│   ├── 新建项目
│   ├── 代码文件上传
│   └── 项目详情
├── 任务看板
├── 风险中心
├── PM 助手
├── 报告中心
├── 系统设置
└── 用户中心（从头像 / 用户名进入）
```

### 4.3 推荐主布局

登录后主布局采用：

```text
左侧导航 + 顶部状态栏 + 主内容区 + 可选右侧线索面板
```

| 区域 | 内容 |
|---|---|
| 左侧导航 | 项目总览、项目管理、任务看板、风险中心、PM 助手、报告中心、系统设置 |
| 顶部状态栏 | 当前项目切换、全局搜索、环境标识、用户头像 |
| 主内容区 | 当前页面主体内容 |
| 右侧线索面板 | 项目风险、Agent 建议、近期动态、待处理事项 |

## 5. 视觉与交互规范

### 5.1 视觉方向

沿用 PM-Agent 已确认的 **Warm Linear workspace style**：

| 颜色 | 用途 |
|---|---|
| `#F8FAF5` / `#FFFFFF` | 页面背景、卡片底色 |
| `#2F7DF6` / `#1F66D1` | 主操作、选中导航、项目进度 |
| `#26B983` / `#15966A` | 健康状态、完成状态、正常推进 |
| `#F5B83D` / `#D8911E` | Agent 洞察、风险提示、注意事项 |
| `#132033` | 主标题、重要数字 |
| `#667085` | 辅助说明、元信息 |
| `#98A2B3` | 空状态、弱提示 |

### 5.2 交互规则

1. 第一阶段不设计复杂拖拽，任务状态切换以按钮、下拉框或轻量操作为主；
2. AI 相关按钮保留位置但置灰，并显示“后续阶段启用”；
3. 上传代码文件需要明确支持压缩包 / 文件夹形式；
4. 删除类操作必须出现二次确认；
5. 高成本扫描、AI 分析、资料解析等动作必须展示成本或次数提示；
6. 所有错误提示、空状态提示和禁用态说明均使用中文。

## 7. 页面设计详述

### 7.1 项目介绍页

#### 界面

项目介绍页是未登录用户看到的公开入口，页面需体现 PM-Agent 的产品定位，而不是普通后台登录入口。

页面结构：

| 区域 | 内容 |
|---|---|
| 顶部导航 | Logo、项目能力、Agent 洞察、登录、注册 |
| Hero 区 | 产品主张、说明文案、进入工作台 CTA、创建账号 CTA |
| 产品预览 | 项目工作台卡片、指标卡片、项目进度、Agent 洞察占位 |
| 价值卡片 | 项目全局视图、任务状态流转、风险线索提示、Agent 洞察、报告生成 |
| 底部 CTA | 登录 / 注册入口 |

核心文案建议：

```text
把项目状态变成可追踪的执行线索
```

#### 接口

项目介绍页不依赖业务接口。

| 接口 | 说明 |
|---|---|
| 无 | 静态公开页面 |

#### 功能

- 展示产品定位；
- 引导用户登录；
- 引导用户注册；
- 对已登录用户可提供“进入工作台”入口。

---

### 7.2 登录页

#### 界面

登录页采用左右分栏：

| 区域 | 内容 |
|---|---|
| 左侧品牌区 | Logo、产品主张、执行线索路径、Agent 洞察预留卡片 |
| 右侧表单区 | 用户名、密码、记住登录、登录按钮、注册链接 |

表单字段：

| 字段 | 控件 | 说明 |
|---|---|---|
| 用户名 | 输入框 | 用户登录名 |
| 密码 | 密码输入框 | 支持显示 / 隐藏密码 |
| 记住登录 | 复选框 | 第一阶段仅作为 UI 展示，可后续扩展 |

#### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/auth/login` | 用户登录 |
| `GET` | `/api/v1/users/me` | 路由刷新后恢复当前用户 |

#### 功能

- 用户输入账号密码登录；
- 登录成功后进入项目总览或原访问页面；
- 登录失败显示中文错误；
- 未登录访问受保护页面时跳转到登录页并保留 redirect。

#### 界面

表单字段：

| 字段 | 控件 | 说明 |

| 用户名 | 输入框 | 用于登录，第一阶段不默认等同邮箱 |

| 密码 | 密码输入框 | 8 到 64 位 |
| 确认密码 | 密码输入框 | 仅前端校验，不提交后端 |

#### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/auth/register` | 注册用户并返回登录态 |

#### 功能

- 用户创建账号；
- 注册成功后自动进入项目总览；
- 用户名重复、参数错误等情况显示中文错误；
- 提供返回登录页入口。

### 7.4 项目总览页

#### 界面

项目总览页是登录后的首页，用于让用户快速判断所有项目的总体状态。

页面结构：

| 区域 | 内容 |
|---|---|
| 页面标题区 | 当前用户问候、全局项目状态说明 |
| 指标卡片 | 项目总数、进行中项目、待处理任务、风险线索、已完成任务 |
| 项目健康概览 | 按项目展示进度、状态、任务完成度 |
| 今日待办 | 与当前用户相关的待处理任务 |
| 近期动态 | 项目创建、任务状态变更、代码资料上传记录 |
| 右侧线索面板 | 风险提示、Agent 建议禁用态、下一步建议 |

#### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/projects` | 获取用户项目列表 |
| `GET` | `/api/v1/tasks?projectId=` | 按项目获取任务，用于汇总任务状态 |
| 待补 | 项目总览聚合接口 | 后续可增加聚合接口减少前端多次请求 |

#### 功能

- 查看所有项目状态；
- 快速进入某个项目；
- 查看当前任务压力；
- 查看风险和 Agent 建议入口；
- 作为用户登录后的默认工作台。

### 7.5 项目管理页

#### 界面

项目管理页关注“项目列表 + 当前选中项目 + 项目操作”。

页面结构：

| 区域 | 内容 |
|---|---|
| 项目筛选栏 | 搜索项目、状态筛选、星标筛选 |
| 项目列表 | 项目卡片或表格，支持星标、进入详情 |
| 当前项目操作区 | 新建项目、上传代码文件、进入任务看板 |
| 任务摘要 | 当前项目任务数量、完成度、优先级分布 |
| AI 分析入口 | “AI 自动设定任务”按钮置灰，显示后续启用说明 |

项目卡片建议字段：

| 字段 | 说明 |
|---|---|
| 项目名称 | 主标题 |
| 项目编码 | 辅助标识 |
| 项目状态 | 未开始、进行中、暂停、延期、完成、归档 |
| 星标 | 用于提高排序位置 |
| 任务完成度 | 已完成 / 总任务数 |
| 负责人 | 第一阶段默认当前用户 |
| 周期 | 开始日期到结束日期 |

#### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/projects` | 获取项目列表 |
| `POST` | `/api/v1/projects` | 新建项目 |
| `GET` | `/api/v1/projects/{id}` | 获取项目详情 |
| 待补 | `PUT /api/v1/projects/{id}/star` | 设置 / 取消项目星标 |
| 待补 | `POST /api/v1/projects/{id}/code-packages` | 上传代码压缩包或文件夹打包结果 |
| 待补 | `GET /api/v1/projects/{id}/code-packages` | 查询项目代码资料 |

#### 功能

- 查看自己的项目；
- 搜索和筛选项目；
- 星标项目并提高排序；
- 新建项目；
- 切换当前操作项目；
- 上传代码压缩包或文件夹；
- 查看当前项目任务摘要；
- 展示 AI 自动设定任务入口，但第一阶段核心按钮置灰。

#### 代码上传设计

第一阶段设计稿需展示“上传代码压缩包 / 文件夹”的完整页面流程。

推荐交互：

```text
点击上传代码文件
  ↓
打开上传弹窗 / 抽屉
  ↓
选择压缩包或文件夹
  ↓
展示文件筛选说明
  ↓
上传前确认
  ↓
展示上传记录和状态
```

上传说明文案建议：

```text
请上传必要源码文件，避免上传 node_modules、target、dist、.git、大型依赖包和密钥文件。
```

上传状态：

| 状态 | 页面表现 |
|---|---|
| 待上传 | 空状态 + 上传按钮 |
| 上传中 | 进度条 + 文件大小 |
| 上传成功 | 文件包名称、上传时间、文件数量、可删除 |
| 上传失败 | 中文错误提示 + 重试按钮 |
| 检测到敏感文件 | 黄色风险提示，提醒用户确认 |

### 7.6 项目详情页

#### 界面

项目详情页展示单个项目的完整上下文，是任务看板、代码资料、风险线索和后续 Agent 分析的承接页。

页面结构：

| 区域 | 内容 |

## 10. 验收标准

### 10.1 Figma 设计稿验收

- 所有第一阶段页面均已在 Figma 中出现；
- 页面命名清晰，符合“页面 / 状态”格式；
- 页面之间的业务流程可通过箭头或布局关系理解；
- AI 相关页面可进入，但核心按钮置灰并有中文说明；
- 代码上传流程有弹窗或抽屉状态；
- 页面不出现设计说明、开发备忘或 Claude 工作过程文字；
- 页面使用真实 PM-Agent 业务文案，不使用 Lorem Ipsum。

### 10.2 前端实现参考验收

- 每个页面能找到对应的接口或待补接口；
- 已有接口与 `docs/05-接口规范.md` 保持一致；
- 写接口在设计文档中明确需要 `X-Idempotency-Key`；
- 页面错误、空状态、禁用态均使用中文；
- 代码上传、风险扫描、资料解析等高成本或高风险能力有明确提示。

---

## 11. 风险与取舍

| 风险 | 说明 | 处理方式 |
|---|---|---|
| 第一阶段页面范围较大 | 页面覆盖项目、任务、风险、助手、报告、设置等完整产品结构 | Figma 先完整表达，开发按接口成熟度分批实现 |
| AI 能力尚未就绪 | 风险扫描、PM 助手、报告生成依赖后续 Agent 能力 | 页面可进入，核心按钮置灰 |
| 代码上传涉及存储与安全 | 需要过滤依赖包、大文件、密钥文件 | 第一阶段先设计上传流程和提示，后端接口单独补设计 |
| 报告中心接近 RAG | 资料解析和知识问答属于后续阶段 | 第一阶段只设计报告和资料管理入口 |
| 系统设置可能扩展过多 | 存储位置、版本、功能开关都可能涉及后端配置 | 第一阶段先保留基础设置和禁用态 |

## 12. 待确认问题

以下问题不影响当前 Figma 页面级设计，但会影响后续前端和后端实现：

1. 代码文件上传的后端存储方式是否使用本地磁盘、数据库记录 + 本地文件，还是后续接入 MinIO；
2. 代码上传支持的文件大小、压缩包格式和文件数量上限需要在后端实现前确认；
3. 风险中心第一阶段是否需要真实保存扫描配置，还是仅展示禁用态；
4. 报告中心第一阶段是否需要真实上传普通资料，还是仅展示资料管理入口；
5. 系统设置中的“存储位置修改”是否允许用户直接修改本地路径，还是只做只读展示；
6. 用户中心第一阶段是否开放修改资料接口，还是仅展示当前用户资料。
