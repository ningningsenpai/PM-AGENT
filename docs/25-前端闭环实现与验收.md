# 前端闭环实现与验收

## 1. 目标与范围

本轮实现“项目 → 文件同步与解析 → PM 助手问答 → 显式学习 → 报告查看”的真实业务闭环。沿用 Vue 3、TypeScript、Naive UI、Pinia、Vue Router 和 Axios，参考 Figma 正式稿的 Warm Linear 配色、侧栏及内容层级。

初批前端接入已有 FastAPI 接口。后续会话交互补充新增会话改名接口，并扩展自动命名及消息关联字段；未新增数据库迁移、模型工具写权限或运行中间件。

## 2. 模块设计

| 模块 | 职责与页面 |
|---|---|
| auth | 邮箱认证、登录恢复、资料修改、密码修改、退出与失效处理 |
| project | 创建、筛选、详情、删除、文件同步计划、文件列表、解析及定向重试 |
| assistant | 持久化会话、普通 JSON 问答、运行记录、工具来源、显式学习与版本纠正 |
| report | 开发／风险报告生成、筛选、历史正文、来源版本、证据及运行详情 |
| workspace | 个人总览、当前项目摘要、有限知识库 |
| task | 保留演示结构；真实模式禁止调用未开放接口 |
| shared | 安全 Markdown、中文错误反馈、时间与身份格式、空项目和能力说明 |

路由携带项目 ID，顶栏提供统一项目选择。每个项目页面独立挂载；文件、会话和报告请求通过页面作用域和请求序号丢弃迟到结果。总览仅聚合当前用户的项目列表，文件及报告摘要只统计当前选中项目。

## 3. 契约与产品边界

- 实际后端成功业务码为 **200**。分析计划及旧文档中的 code=0 不符合当前响应模型，已修正文档与请求层。
- 所有雪花 ID 使用十进制字符串；文件 ID、lockVersion 和学习条目 version 使用数字。
- 项目、会话、报告和记忆时间按 UTC 显示；认证模块的 lastLoginAt 当前为无时区的服务端本地时间，资料页明确标注“服务端时间”，保留其原始钟面值。后端统一时区属于后续契约治理。
- 初始化成功代表项目存储和上下文空间就绪，不代表业务进度或文件解析成功。
- 创建项目仅提交 projectName；没有可保存接口的项目编码、说明、业务周期及成员字段不再作为创建表单输入。
- 文件同步继续复用规划、内容指纹、移动识别、防重、版本校验和删除确认。解析单独触发，不生成任务。
- 问答及学习使用持久化会话接口；当前 API 未开放 SSE。
- 学习由用户显式确认。支持查看有效、待确认、失效和过期条目，纠正需提交 version 与 reason；词条映射通过对话纠正后重新学习。
- 学习内容提交和快照发布分别显示；发布失败可重发快照，不重复调用学习模型。
- 开发／风险报告保存独立历史记录；没有编辑、发布、归档或周报周期状态。
- 任务、需求、迭代、风险处置、全局动态、消息读写和系统配置保存暂未开放。

## 4. 请求恢复与内容安全

问答、学习和报告将幂等键、操作类型、原始参数和已知 runId 暂存在 sessionStorage，按用户、项目和会话隔离。请求中断后使用原操作恢复；已知 runId 只查询运行。明确终态后清理暂存参数，后续显式执行才生成新键。退出清理恢复记录，未完成请求的迟到结果不会恢复已退出的状态。

后端运行状态独立于 HTTP 及业务响应码。界面分别呈现 running、success、failed；文件解析保留 partial、规范构建失败及索引发布失败。传输错误和系统异常保留“结果待确认”状态。

使用 markdown-it 15，关闭原始 HTML 和图片加载；来源链接使用独立标签页及 noopener/noreferrer。模型回答、报告、文件名和证据按不可信内容处理。证据片段保留原始行号、来源类型、截断标记及用户消息 ID。

## 7. 验收限制

浏览器“开始生成报告”曾被自动审批审核拒绝，要求明确授权向 DeepSeek 发送具体测试数据。随后只读检查发现开发报告已存在，因此报告历史读取、证据和刷新恢复已完成核验；不将该次受审核影响的点击作为稳定通过的自动化生成步骤。风险报告真实生成及新增模型调用仍待授权；两类生成请求的接口适配已由契约测试覆盖。

实际断网、同步部分失败和模型失败未通过破坏中间件的方式重现。本轮用轻量契约测试覆盖前端失败恢复，后端既有测试继续作为补充；不能将这些结果表述为生产验收完成。

当前按需注册 Naive UI 后，主包由约 1.5 MB 降至约 0.76 MB（压缩前），仍有 Vite 大包提示；未为消除提示引入额外分包体系。Figma 助手图片为原始导出资源。

## 9. 文件解析进度交互补充

解析确认弹窗在点击“开始解析”后保持打开，展示本轮已处理文件数、总数和百分比。前端在提交前获取候选文件快照，随后每 1.5 秒读取文件列表；后端每次解析成功或失败都会提交 parseAttempts 的递增，前端据此识别本轮已处理文件。定向重试以开始前的尝试次数作为基线，历史成功不计入本轮进度。

进度条表示文件处理比例，达到 100% 后若后端还在更新项目规范与索引，继续显示等待状态。最终响应返回后展示成功、部分失败及发布状态，保留弹窗供用户核对。无候选文件时等待上下文更新，收到最终结果后显示 100%；请求失败不会显示成功。

页面“解析项目文件”、定向重试和弹窗“开始解析”共用提交锁定；忙碌期间禁止关闭弹窗和页面内路由切换。轮询串行执行，读取失败不会重发解析请求，终态或组件销毁后停止轮询并丢弃迟到结果。此处防重限于当前页面生命周期，不代表后端已具备跨标签页或浏览器刷新后的批次幂等能力。

新增 5 项自动检查覆盖本轮候选计数、定向重试、重复提交、轮询失败、迟到结果、无候选文件及组件销毁。浏览器使用独立本地响应样例核验弹窗和进度展示，不调用真实模型，不修改项目文件；未将该验证表述为新增真实模型验收。

## 10. PM 助手会话交互补充

新建会话直接创建并选中，由后端按项目生成“项目对话-N”；标题旁提供改名按钮，输入首尾空白会去除，最多 128 个字符。服务端同时校验用户和项目归属，改名结果写入既有会话表。历史列表移除原有 100 条截断，全部会话在列表内部滚动。

助手顶部压缩为标题说明和页签，会话列表、对话主体、运行记录填满剩余窗口高度。消息区和会话列表独立滚动，发送栏保持在主体底部。Enter 发送，Shift + Enter 换行；中文输入法确认和长按 Enter 不触发发送。消息提交时立即显示本地用户消息与等待状态，服务端历史按请求标识或运行消息 ID 替换，不按正文去重。结果未确认时沿用原幂等键恢复，失败运行保留错误提示。

本次后端会话单元测试共 21 项通过，其中新增 4 项覆盖自动编号、改名后编号及项目隔离、超过 100 条历史、改名接口校验和权限、消息请求标识。使用 SQLite 内存库与确定性 Agent 样例，未验证 MySQL 并发锁，也未调用真实模型。

浏览器使用独立本地响应样例加载真实页面组件，验证连续新建、改名后刷新列表、Shift + Enter 不发送、Enter 只提交一次且回答前显示用户消息。1280 × 720 窗口中，增加 35 条历史与长回答后，会话栏和对话主体高度均保持约 501px，页面高度保持 720px；历史列表和消息区分别产生内部滚动。回答返回后用户消息仅保留一条。样例没有访问业务后端或模型，验收结束后移除。
