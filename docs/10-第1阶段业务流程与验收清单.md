# 第 1 阶段业务流程与验收清单

## 1. 背景

第 1 阶段目标是完成 PM-Agent 的最小业务闭环：用户登录后可以查看项目、创建项目、在项目下创建任务，并通过任务看板查看与切换任务状态。

本阶段不追求复杂协作能力，不提前引入需求管理、迭代管理、风险自动分析、Agent 对话、RAG 或完整 RBAC。重点是让前端、后端、数据库和本地中间件配置形成可运行、可演示、可继续扩展的基础骨架。

---

## 2. 目标

1. 明确第 1 阶段从登录到任务看板的完整业务流；
2. 明确后端接口、数据库表、前端页面之间的对应关系；
3. 确认开发前置工作已经完成，可以进入工程初始化；
4. 提供后续手动验收的最小清单。

---

## 3. 范围

### 3.1 本期范围

| 模块 | 本期能力 |
|---|---|
| 用户与认证 | 注册、登录、登出、获取当前用户 |
| 项目管理 | 创建项目、项目列表、项目详情 |
| 项目成员 | 初始化项目成员关系，为后续权限扩展预留基础 |
| 任务管理 | 创建任务、任务列表、任务状态切换 |
| 任务看板 | 按任务状态分组展示，通过下拉框切换状态 |
| 状态日志 | 任务状态变化写入 `pm_task_status_log` |
| 接口规范 | 统一响应、错误码、traceId、幂等键 |
| 本地演示数据 | 初始化默认用户、示例项目、若干示例任务 |

### 3.2 不做范围

## 4. 核心业务流程

### 4.1 整体流程

```text
启动 MySQL 容器
  ↓
启动后端 Spring Boot
  ↓
Flyway 创建表并初始化演示数据
  ↓
启动前端 Vite
  ↓
用户登录
  ↓
进入主布局
  ↓
查看项目列表
  ↓
创建或进入项目详情
  ↓
查看项目任务
  ↓
在任务看板中按状态分组展示
  ↓
通过下拉框切换任务状态
  ↓
后端更新任务状态并写入任务状态日志
```

---

### 4.2 登录流程

```text
用户输入用户名和密码
  ↓
前端调用 POST /api/v1/auth/login
  ↓
后端校验用户状态和密码
  ↓
Sa-Token 生成登录态
  ↓
后端返回统一响应与 traceId
  ↓
前端保存登录态
  ↓
跳转到项目列表页
```

涉及内容：

| 类型 | 内容 |
|---|---|
| 数据表 | `pm_user` |
| 后端接口 | `POST /api/v1/auth/register`、`POST /api/v1/auth/login`、`POST /api/v1/auth/logout`、`GET /api/v1/users/me` |
| 前端页面 | 登录页 |
| 关键规则 | 用户必须为 `enabled` 状态；错误提示使用中文 |

---

### 4.3 项目流程

```text
用户登录
  ↓
进入项目列表页
  ↓
前端调用 GET /api/v1/projects
  ↓
后端返回当前用户可见项目
  ↓
用户创建项目或进入项目详情
  ↓
创建项目时同步维护项目负责人和项目成员关系
```

涉及内容：

| 类型 | 内容 |
|---|---|
| 数据表 | `pm_project`、`pm_project_member` |
| 后端接口 | `POST /api/v1/projects`、`GET /api/v1/projects`、`GET /api/v1/projects/{id}` |
| 前端页面 | 项目列表页、项目详情页 |
| 关键规则 | 第 1 阶段只要求登录可访问；复杂项目角色权限第 2 阶段实现 |

---

### 4.4 任务流程

```text
用户进入项目详情
  ↓
查看任务列表或任务看板
  ↓
创建任务
  ↓
任务默认进入待处理状态
  ↓
前端按状态分组展示任务
  ↓
用户通过下拉框切换状态
  ↓
后端校验状态流转是否合法
  ↓
更新 pm_task.status
  ↓
写入 pm_task_status_log
  ↓
前端刷新看板数据
```

涉及内容：

| 类型 | 内容 |
|---|---|
| 数据表 | `pm_task`、`pm_task_status_log` |
| 后端接口 | `POST /api/v1/tasks`、`GET /api/v1/tasks?projectId=`、`PUT /api/v1/tasks/{id}/status` |
| 前端页面 | 任务看板页 |
| 关键规则 | 第 1 阶段使用下拉框切换状态；拖拽能力后置 |

---

## 5. 任务状态流转

第 1 阶段任务状态沿用项目业务流程约定：

```text
待处理 → 开发中 → 待联调 → 待测试 → 已完成
       ↘ 已取消
```

建议状态 code：

| 展示名 | code | 说明 |
|---|---|---|
| 待处理 | `pending` | 新建任务默认状态 |
| 开发中 | `developing` | 任务正在执行 |
| 待联调 | `integrating` | 等待联调或正在联调 |
| 待测试 | `testing` | 等待测试或正在测试 |
| 已完成 | `done` | 任务完成 |
| 已取消 | `cancelled` | 任务不再执行 |

第 1 阶段可以先实现基础合法流转，复杂状态机和拖拽规则第 2 阶段增强。

## 8. 验收标准

### 8.1 后端验收

- MySQL 容器可以正常启动；
- 后端启动后 Flyway 能自动创建第 1 阶段表；
- 默认用户、示例项目、示例任务初始化成功；
- Knife4j 可访问；
- 登录、当前用户、项目、任务接口可调试；
- 所有响应包含 `code`、`message`、`data`、`traceId`；
- 写接口缺少 `X-Idempotency-Key` 时返回中文错误提示；
- 切换任务状态后写入 `pm_task_status_log`。

### 8.2 前端验收

- 前端可通过 pnpm 启动；
- 登录页可通过注册用户或已配置可用密码的用户登录；
- 项目列表页可展示示例项目；
- 项目详情页可展示项目基础信息；
- 任务看板页可按状态分组展示示例任务；
- 任务状态可通过下拉框切换；
- 后端接口未完成时，本地 Mock 层可支撑页面开发。

### 8.3 联调验收

- 前端请求自动带上 `X-Trace-Id`；
- 写接口自动带上 `X-Idempotency-Key`；
- 登录态能被后端识别；
- 项目和任务页面能从 Mock 切换到真实接口；
- 任务状态切换后看板展示同步更新。
