# 01 开发规划

本文档说明 PM-Agent 智能项目管理 Agent 平台的分阶段开发计划。整体遵循 **垂直切片** 与 **技术点解耦** 两条原则，避免单人开发节奏失控。

---

## 一、总原则

1. **垂直切片优先**：每个阶段都要有“可演示的前后端闭环”，不积压一堆后端再补前端。
2. **新增技术解耦**：每个阶段最多引入 1–2 个新中间件或新技术点。
3. **MVP 思维**：先跑通主线，再补细节；初期数据模型预留扩展字段，避免后期改主键和核心字段。
4. **以增强为目标，不重构核心**：每个阶段的产物在后续阶段只增不改。
5. **Agent 渐进接入**：先做传统业务，再做对话，再做工具调用，再做风险分析与 RAG。

---

## 二、阶段总览

| 阶段 | 主题 | 核心交付 | 新增技术 |
|---|---|---|---|
| 第 1 阶段 | 项目骨架 | 用户、项目、任务最小闭环 | Spring Boot 3、Sa-Token、MyBatis Plus、Vue 3 + Naive UI |
| 第 2 阶段 | 项目管理 MVP | 需求、迭代、风险、看板 | Redis、状态机、RBAC |
| 第 3 阶段 | Agent 对话 | 项目问答、对话落库 | Python FastAPI、Prompt 模板、模型路由 |
| 第 4 阶段 | Agent 工具调用 | 周报生成、需求拆解、状态查询 | Tool Calling、Agent Trace 可视化 |
| 第 5 阶段 | 风险分析 | 延期识别、阻塞分析、人员负载 | RabbitMQ、定时任务、规则引擎 |
| 第 6 阶段 | RAG 知识库 | 文档管理、会议纪要、知识问答 | MinIO、Qdrant 或 pgvector |
| 第 7 阶段 | 企业级完善 | 通知、审计、报告导出、数据看板 | ECharts 看板、通知渠道 |

---

## 三、第 1 阶段：项目骨架

### 3.1 目标

完成最小闭环：登录、看到项目、创建任务、看板查看任务状态。

### 3.2 后端任务

- 初始化 Spring Boot 3 工程，构建工具使用 Maven，包结构按 `com.ning.pm.<module>`；
- 集成 Sa-Token，提供登录、登出、当前用户、权限校验；
- 集成 MyBatis Plus + MySQL；
- 使用 Flyway 管理数据库迁移脚本；
- 表：`pm_user`、`pm_project`、`pm_project_member`、`pm_task`、`pm_task_status_log`；
- 接口：
  - `POST /api/v1/auth/login`
  - `GET  /api/v1/auth/me`
  - `POST /api/v1/projects`
  - `GET  /api/v1/projects`
  - `GET  /api/v1/projects/{id}`
  - `POST /api/v1/tasks`
  - `GET  /api/v1/tasks?projectId=`
  - `PUT  /api/v1/tasks/{id}/status`
- 统一响应结构、统一异常处理、统一日志格式；
- Knife4j 接口文档可访问。

### 3.3 前端任务

- 初始化 Vue 3 + TypeScript + Vite，Node.js 版本锁定 Node 20 LTS，包管理器使用 pnpm；
- 集成 Naive UI、Pinia、Vue Router、Axios；
- 全局布局：侧边栏 + 顶部 + 主内容区；
- 页面：登录页、项目列表页、项目详情页、任务看板页；
- 状态管理：用户、项目、任务；
- HTTP 封装：请求拦截、错误码处理、登录态注入；
- 开发期提供简单本地 Mock 层，接口未完成前模拟登录、项目和任务数据；
- 任务看板第 1 阶段使用下拉框切换任务状态，拖拽能力后置。

### 3.4 验收标准

- 用户可以登录系统并保持登录态；
- 用户可以创建项目并查看列表；
- 用户可以在项目下创建任务；
- 任务可以在看板中按状态分组展示，并可通过下拉框切换状态；
- 每次任务状态变更写入 `pm_task_status_log`；
- 后端接口可通过 Knife4j 调试。

---

## 四、第 2 阶段：项目管理 MVP

### 4.1 目标

补齐传统项目管理能力，让 MVP 具备实际可用性。

### 4.2 后端任务

- 引入 Redis（缓存与 Sa-Token 会话）；
- 表新增：`pm_requirement`、`pm_iteration`、`pm_task_dependency`、`pm_risk`、`pm_task_status_log`；
- 任务状态机：待处理、开发中、待联调、待测试、已完成、已取消；
- 需求-任务关联、迭代-任务关联；
- 风险列表与处理状态；
- RBAC：项目经理、研发、测试、管理员四类角色；
- 列表统一支持分页、排序、过滤。

### 4.3 前端任务

- 项目详情页扩展：需求、任务、迭代、风险四个 Tab；
- 看板支持按负责人筛选、按优先级筛选；拖拽能力后续按状态流转规则评估是否加入；
- 风险列表与风险详情卡片；
- 角色管理与项目成员管理基础页面。

### 4.4 验收标准

- 可以创建需求并关联到任务；
- 可以规划迭代、查看迭代进度；
- 可以手动创建风险并跟踪状态；
- 不同角色看到的功能入口不同。

---

## 五、第 3 阶段：Agent 对话

### 5.1 目标

为系统接入第一版 Agent，支持项目自然语言问答。

### 5.2 新增组件

- Python FastAPI 服务（`agent-service/`）；
- Java 通过 HTTP 调用 Python 服务；
- 接入第一组模型（默认 DeepSeek，可切换 Claude / GPT）。

### 5.3 任务清单

- Java：
  - `POST /api/v1/agent/chat`（透传到 Python）；
  - `agent_session`、`agent_message` 落库；
  - 鉴权与权限注入。
- Python：
  - Prompt 模板管理；
  - 模型路由（默认/升级两档）；
  - 流式输出；
  - 简单的会话上下文窗口控制。
- 前端：
  - Agent 助手页；
  - 流式输出展示；
  - 会话历史；
  - 一键“查询当前项目状态”等预置问题。

### 5.4 验收标准

- 用户可以与 Agent 对话；
- Agent 能基于 Prompt 回答关于项目管理的通用问题；
- 会话历史可查询。

---

## 六、第 4 阶段：Agent 工具调用

### 6.1 目标

让 Agent 不再只是聊天，能查询并推动业务。

### 6.2 工具清单（首批）

- `query_project_overview`
- `query_task_list`
- `query_overdue_tasks`
- `query_member_workload`
- `split_requirement_into_tasks`
- `generate_weekly_report`

### 6.3 任务清单

- Java：为每个工具提供内部 API，统一权限和审计；
- Python：
  - Tool Calling 链路；
  - `agent_trace`、`agent_tool_call` 完整落库；
  - 结构化输出校验。
- 前端：
  - Agent 执行链路可视化（输入、工具调用、结果）；
  - 一键生成周报按钮；
  - 一键拆分需求按钮。

### 6.4 验收标准

- Agent 可以自动调用工具回答“当前项目有哪些延期任务？”；
- Agent 可以拆分需求为任务并展示结果；
- 所有调用可在 Trace 页查看。

---

## 七、第 5 阶段：风险分析

### 7.1 目标

让系统主动发现风险，而不是等用户登记。

### 7.2 任务清单

- 引入 RabbitMQ 用于异步分析与通知；
- 定时任务：每日扫描任务延期、阻塞、负载；
- 规则引擎：风险等级评分（高、中、低）；
- Agent：基于规则结果生成自然语言风险说明与建议；
- 前端：
  - 风险中心首页；
  - 风险趋势图；
  - Agent 风险建议卡片；
  - 风险处理闭环。

### 7.3 验收标准

- 系统能自动生成风险并推送给项目经理；
- 风险有等级、原因、建议、处理人；
- 风险关闭后留有处理记录。

---

## 八、第 6 阶段：RAG 知识库

### 8.1 目标

接入企业知识，使 Agent 能基于真实文档回答。

### 8.2 任务清单

- 引入 MinIO 存储文档与附件；
- 引入 Qdrant 或 pgvector 用于向量检索；
- 文档解析：PDF、Word、Markdown、会议纪要；
- 文档切片、向量化、检索、重排序；
- Agent：
  - `search_knowledge` 工具；
  - 引用来源返回；
  - 多轮追问。
- 前端：
  - 文档管理页；
  - 知识问答页；
  - 引用来源展示。

### 8.3 验收标准

- 用户可以上传项目文档并进行问答；
- Agent 回答中包含引用来源；
- 历史会议纪要可被检索。

---

## 九、第 7 阶段：企业级完善

> **审计日志归属此阶段（或更早增强）**：第 1 阶段仅保留 `@AuditLog` 注解占位与 AOP 切面空实现，便于后续填充；覆盖范围（写操作 / 鉴权事件 / Agent 高风险动作 / 敏感读）由本阶段开工前敲定。Agent Trace 不在此延期范围内，按第 3 阶段计划落地。

### 9.1 目标

让系统具备企业级体验和可演示性。

### 9.2 任务清单

- 通知中心（站内消息 + 邮件，企微/钉钉可选）；
- 审计日志查询；
- 报告导出（Markdown / Word / PDF）；
- 数据看板（项目、人员、风险趋势）；
- 系统设置（模型配置、Prompt 模板、工具开关）；
- 监控指标（Prometheus + Grafana 可选）。

### 9.3 验收标准

- 项目主管可以查看整体看板；
- 报告可一键导出；
- 关键操作可在审计日志中追溯。

---

## 十、风险与取舍

| 风险 | 应对 |
|---|---|
| 单人开发节奏失控 | 严格按阶段交付，不跨阶段堆功能 |
| Agent 输出不稳定 | 关键能力使用结构化输出 + Schema 校验 |
| LLM 成本失控 | 默认低成本模型，关键任务再升级 |
| 中间件过早引入 | 严格按阶段表引入，不提前 |
| 数据模型反复改 | 第 1–2 阶段集中评审表结构，后续只增字段 |
