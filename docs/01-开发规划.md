# 开发规划

## 1. 当前基线

在线运行架构已经收敛为：

```text
Vue 3 → FastAPI 模块化单体 → MySQL / Redis / MinIO / LLM
```

当前已具备认证、用户、项目、项目文件、文件解析与 Agent 对话基座。Python 是业务数据唯一写入者，Alembic 是数据库结构唯一迁移工具。

## 2. 开发原则

1. 以可验收的前后端垂直切片推进；
2. 新业务放入独立 `app/modules/<module>/`；
3. Agent 只能通过公开 Service 使用业务能力；
4. 外部 MinIO、Redis、LLM 调用不放在数据库事务内；
5. 高风险写操作需要权限、幂等、Trace 与人工确认；
6. 中间件按需求引入，不提前启用 RabbitMQ 或完整 RAG；
7. 不把训练、评测和实验代码混入在线业务模块。

## 3. 后续阶段

| 阶段 | 目标 | 主要交付 |
|---|---|---|
| A | 稳定 Python 在线基座 | 真实环境联调、监控、备份与迁移演练 |
| B | 项目执行闭环 | 任务、需求、迭代、风险模块与前端页面 |
| C | Agent 工具闭环 | 只读查询工具、确认式写工具、Agent Trace |
| D | 报告能力 | 周报、会议纪要、风险摘要与可追溯证据 |
| E | 受控知识检索 | 文档切分、检索评估、按需启用向量基础设施 |

## 4. 每个模块的完成标准

- API、Schema、Domain、Repository、Service、Errors 边界清晰；
- 数据结构由新增 Alembic revision 管理；
- 统一响应、中文错误和 traceId 保持一致；
- 单元测试覆盖领域不变量和异常路径；
- 契约测试覆盖权限、幂等和响应结构；
- 前端类型检查、生产构建和关键页面交互通过；
- 文档同步更新；
- 受保护 Agent 资产没有无关差异。

## 5. 当前不做

- 双后端运行和业务表双写；
- RabbitMQ 文件链路；
- 模型生成 SQL 的直接执行；
- 未经确认的高风险 Agent 自动操作；
- 完整训练、评测或 RAG 产品化。
