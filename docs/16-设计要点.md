# 16-设计要点

## 1. 文档定位

本文用于记录 PM-Agent 后续设计与开发必须遵循的关键结论，来源于 Figma 终稿设计讨论、个人开发者版需求讨论、主界面框架统一和项目管理业务重构讨论。

本文只记录会影响后续开发设计的重要思想，不记录临时尝试、聊天过程、插件使用过程和已废弃方案。

后续每一轮对话中，如果出现会影响页面设计、接口口径、数据模型、Agent 能力或开发边界的关键信息，应同步更新本文。

## 2. Figma 终稿维护规则

当前正式设计稿以 `PM Agent终稿` 为准：

```text
https://www.figma.com/design/9HMUagdeXhbnvDG6kRMUem/PM-Agent%E7%BB%88%E7%A8%BF?node-id=0-1&m=dev
```

旧初稿链接不再作为后续修改依据。

每个业务步骤完成后，后续业务中除非明确要求，不再修改已经完成并确认的稿件。新增或修改页面时，应只触达当前业务范围内的页面和组件。

设计主线调整为设计驱动开发：先补全 Figma 终稿设计，再根据设计稿驱动前端、接口和后端实现。

## 3. 总体产品与设计原则

PM-Agent 第一版本优先面向个人开发者和单人项目管理者，不提前引入复杂组织、多租户协作、企业级 RBAC、多级审批、完整 BI 或复杂 DevOps 能力。

页面设计应围绕个人项目管理闭环展开：

- 项目
- 需求
- 任务
- 迭代
- 风险
- 报告
- Agent 辅助分析

业务主界面的核心原则：

1. 统一工作台框架不随业务页面变化。
2. 左侧导航、Logo 区、顶部搜索框和个人信息是后续主界面底座。
3. 每个业务页面只替换主内容区。
4. 每个页面必须明确页面职责、展示内容、数据来源、核心操作和状态闭环。
5. 默认态、空状态、操作态、异常态或禁用态应成体系。
6. 设计中可以预留 Agent 和后续能力入口，但未实现能力必须以禁用态或后续启用提示表达。

## 8. 项目管理页设计方向

`项目管理页 / 默认` 后续应从“项目列表页”调整为“单项目工作台”。

核心设计方向：

1. 页面一次只展示一个当前项目。
2. 项目切换通过顶部或内容区内的项目下拉菜单完成。
3. 项目名称后展示星标，用户可自由选择置顶或取消置顶。
4. 项目列表不再作为页面主体大面积出现。
5. 页面主体展示当前项目的状态、进度、任务、风险、资料和 PM助手入口。

`项目管理页 / 默认` 已采用“执行总览型”方案：页面清晰、实现成本可控，也能自然承接后续 PM助手能力。

### 8.1 项目管理页需要展示的信息

| 展示内容 | 说明 |
|---|---|
| 当前项目选择区 | 项目下拉菜单、项目名称、星标置顶、项目状态、最近更新时间 |
| 项目基础信息 | 项目编号、负责人、起止时间、当前迭代、项目描述 |
| 核心指标 | 任务完成率、需求数量、风险数量、文件数量、最近活跃时间 |

| 项目资料 | 已选择的项目文件、代码包或文档、可分析状态、重新选择文件入口 |
| PM助手入口 | 分析风险、拆解任务、总结项目状态、生成周报草稿等入口 |

### 8.4 默认页已确认布局

`项目管理页 / 默认` 是当前项目的单项目工作台，不再作为项目列表页使用。

页头规则：

- 原“项目管理”标题位置替换为具体项目名称，例如 `PM-Agent 平台 MVP`。
- 项目名称后紧接项目切换下拉按钮。
- 点击项目切换按钮后展示项目菜单，项目菜单按星标置顶和最近更新时间排序。
- 右侧保留 `新建项目` 按钮。
- 原 `上传代码` 按钮改为 `更新项目`，用于更新当前项目资料、源码文件或项目元信息。
- 页面标题下方不再展示说明文案和页面内搜索框；顶部全局搜索框仍属于主界面固定框架。

主体区域分为三块：

| 区域 | 位置与比例 | 页面职责 | 颜色语义 |
|---|---|---|---|
| 任务速览 | 左上，左侧区域高度约五分之三 | 展示当前项目任务中最需要关注和可顺序推进的事项 | 黄色表示需要关注、尽快开发；绿色表示可以顺序进行 |
| 风险速览 | 左下，左侧区域高度约五分之二 | 展示当前项目严重风险和一般风险 | 柔和红表示严重风险、需要尽快处理；绿色表示一般风险、可进入特定周期处理 |
| 进度简报 | 右侧，高度与左侧两块合计对齐 | 展示 PM助手月半猫基于当前项目生成的开发回顾、迭代信息和开发建议 | 以蓝色结构线、黄色建议提示承载 Agent 分析结果 |

任务速览的视觉形式沿用原“我的项目”行式卡片风格：左侧色条表达优先级，中间展示任务名称和说明，右侧展示状态标签。

风险速览的严重风险示例包括支付模板依赖未确认、敏感文件过滤策略缺失；一般风险示例包括 MVP 支付模板可延期。

进度简报由 PM助手月半猫生成，内容应围绕：

- 本轮开发回顾
- 当前迭代信息
- 下一步开发建议
- 需要补齐的数据或接口口径

### 8.6 新建项目与初始化流程

新建项目弹窗已调整：

- 删除 `项目编码` 输入框。
- 将原项目编码位置改为 `项目文件夹` 链接组件。
- 点击 `选择项目文件夹` 后打开本地文件夹选择器，由用户选择项目根目录。
- 新建项目时不再单独进入“上传代码文件弹窗”。
- `项目管理页 / 上传代码文件弹窗` 设计界面已删除。

新建项目后的初始化流程：

1. 用户在新建项目弹窗中填写项目信息并选择项目文件夹。
2. 点击创建后进入 `项目初始化页 / 通用解析中`。
3. 系统扫描项目文件结构、识别技术栈、抽取风险线索并生成初始化简报。
4. 解析期间，项目相关页面暂时显示初始化态。
5. 如果是第一个项目，初始化态需要覆盖个人工作台；如果不是第一个项目，个人工作台不强制进入初始化态。
6. 解析完成后进入 `项目管理页 / 解析完成待拆解`。

`项目初始化页 / 通用解析中` 覆盖范围：

- 个人工作台
- 项目管理
- 任务看板
- 风控中心

`项目管理页 / 解析完成待拆解` 的展示规则：

- 展示 `进度简报` 组件。
- 展示 `风险速览` 组件。
- `任务速览` 暂不展示真实任务，使用占位字符标识任务拆解结果待生成。
- 解析完成后的任务看板和风控中心界面暂不在本轮生成，等后续进入对应设计稿时再补齐。

## 9. 多项目协调原则

`项目管理`、`任务看板`、`风控中心` 三个模块涉及多项目时，必须遵守同一上下文原则：

项目是主上下文，任务和风险都必须归属到具体项目。跨项目只做聚合视图，不把业务数据复制到多个模块里。

### 9.1 模块职责

| 模块 | 默认视角 | 职责 |
|---|---|---|
| 项目管理 | 单项目 | 展示项目基础信息、进度、资料、任务摘要、风险摘要 |
| 任务看板 | 当前项目 | 展示和操作当前项目任务 |
| 风控中心 | 当前项目 | 展示和处理当前项目风险 |
| 个人工作台 | 全部项目聚合 | 展示跨项目待办、逾期任务、风险总览、最近活动 |

任务看板和风控中心可以提供“全部项目”筛选，但该筛选只用于查询聚合。每条任务或风险仍必须显示所属项目，写操作必须回到具体项目上下文。

### 9.2 跨页面项目上下文

用户从项目管理页进入任务看板或风控中心时，应携带当前 `projectId`。

项目切换后，项目管理、任务看板和风控中心读取同一项目上下文。

建议路由或状态管理中维护当前项目：

```text
currentProjectId
```

页面级查询统一围绕 `projectId` 发起。

## 10. 数据一致性原则

项目、任务、风险、需求、迭代和项目文件必须遵循“单一事实源”。

| 数据 | 唯一事实源 |
|---|---|
| 项目基础信息 | `pm_project` |
| 任务 | `pm_task.project_id` |
| 风险 | `pm_risk.project_id` |
| 需求 | `pm_requirement.project_id` |
| 迭代 | `pm_iteration.project_id` |
| 项目文件 | 项目文件或代码资料表的 `project_id` |
| 统计数据 | 从任务、风险、需求等表聚合计算 |

不要在项目表中长期保存“任务完成数、风险数量”这类容易过期的统计值。页面需要时应通过聚合接口返回，例如：

```text
GET /api/v1/projects/{id}/overview
```

如果后续为了性能引入缓存，也必须以任务、风险、需求、迭代等变更事件刷新缓存。

写操作必须校验：

- 所属项目存在
- 所属项目未删除
- 当前用户有权限访问该项目
- 写接口携带 `X-Idempotency-Key`

任务状态变化应写入 `pm_task_status_log`。风险处理过程应写入 `pm_risk_event`。Agent 相关执行记录应写入独立的 Agent Trace 表，不混入业务状态日志。

## 12. Agent 设计边界

Agent 不直接操作业务数据库。所有业务变更必须通过 Java 后端提供的受控工具 API 完成。

Agent 生成的任务、风险、报告等业务结果应先成为草稿或候选，必须由用户人工确认后再落库。

高风险动作必须人工确认，包括：

- 删除
- 权限变更
- 批量创建任务
- 创建风险候选
- 对外通知
- 状态批量变更

Agent Trace 与业务日志分离。Trace 用于记录模型调用、工具调用、耗时、输入输出摘要、错误和 token 使用情况。
