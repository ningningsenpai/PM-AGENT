# 04 数据模型

本文档定义 PM-Agent 智能项目管理 Agent 平台的数据模型原则、通用字段、核心表结构、状态枚举、数据字典与 Agent Trace 设计。所有表结构设计必须对齐 `docs/00-术语表.md`。

---

## 1. 背景

PM-Agent 需要同时支撑传统项目管理业务和 Agent 智能分析能力。数据模型必须满足：

- 项目、需求、任务、迭代、风险、报告等业务对象可结构化管理；
- Agent 能通过工具 API 查询业务数据并形成可追踪决策；
- 后续多租户、RAG、审计日志、报表统计可扩展；
- 第一版不为了“通用平台”过度抽象。

---

## 2. 建模原则

1. 主数据库使用 MySQL 8；
2. 表名使用小写下划线，业务表以 `pm_` 开头，Agent 表以 `agent_` 开头，系统表以 `sys_` 开头；
3. 所有业务表预留 `tenant_id BIGINT NOT NULL DEFAULT 0`，第 1 阶段不启用多租户过滤；
4. 默认逻辑删除，部分大表后续可按日期归档或物理清理；
5. 状态字段使用小写字符串 code，不使用数字字典；
6. 核心状态机字段采用“代码枚举 + 数据字典展示”双轨；
7. Agent Trace 独立建模，不与业务审计日志混用；
8. 不使用 UUID 作为普通业务主键，`traceId` 除外。

---

## 3. 通用字段

### 3.1 BaseEntity 字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 是 | 无 | 主键，自增或雪花，按表策略确定 |
| `tenant_id` | BIGINT | 是 | 0 | 多租户预留字段 |
| `created_by` | BIGINT | 否 | NULL | 创建人 ID |
| `created_at` | DATETIME | 是 | 当前时间 | 创建时间 |
| `updated_by` | BIGINT | 否 | NULL | 更新人 ID |
| `updated_at` | DATETIME | 是 | 当前时间 | 更新时间 |
| `deleted` | TINYINT | 是 | 0 | 逻辑删除标记，0 未删除，1 已删除 |

### 3.2 ID 策略

| 场景 | 策略 | 说明 |
|---|---|---|
| 普通业务主表 | 自增 BIGINT | 简单、性能好，适合单体 MVP |
| 敏感或不希望暴露规模的表 | 雪花 ID | 如 Agent Trace、报告编号等 |
| `traceId` | UUID 去横线字符串 | 仅用于链路追踪 |
| `X-Idempotency-Key` | UUID | 前端或 Agent 生成，不作为业务主键 |

## 5. 第 2 阶段业务表

### 5.1 `pm_requirement` 需求表

核心字段：`id、tenant_id、project_id、title、description、source、priority、status、created_by、created_at、updated_at、deleted`。

建议状态：`draft`、`reviewing`、`confirmed`、`developing`、`delivered`、`accepted`、`online`、`cancelled`。

### 5.2 `pm_requirement_change_log` 需求变更日志表

记录已确认需求的变更历史。核心字段：`id、tenant_id、requirement_id、change_type、before_json、after_json、operator_id、reason、trace_id、created_at`。

### 5.3 `pm_iteration` 迭代表

统一承载敏捷 Sprint 与瀑布阶段。

核心字段：`id、tenant_id、project_id、name、goal、status、start_date、end_date、review_summary、created_by、created_at、updated_at、deleted`。

建议状态：`not_started`、`running`、`ended`、`reviewed`。

### 5.4 `pm_iteration_task` 迭代任务关系表

核心字段：`id、tenant_id、iteration_id、task_id、sort_order、created_at、deleted`。

### 5.5 `pm_task_dependency` 任务依赖表

核心字段：`id、tenant_id、task_id、depends_on_task_id、dependency_type、created_by、created_at、deleted`。

唯一约束：`uk_task_dependency(task_id, depends_on_task_id, deleted)`。

### 5.6 `pm_risk` 风险表

核心字段：`id、tenant_id、project_id、task_id、title、description、category、level、status、source、owner_id、identified_at、confirmed_by、confirmed_at、closed_at、created_at、updated_at、deleted`。

建议状态：`draft`、`confirmed`、`rejected`、`mitigating`、`resolved`、`closed`。

### 5.7 `pm_risk_event` 风险事件表

记录风险确认、处理、关闭过程。核心字段：`id、tenant_id、risk_id、event_type、content、operator_id、trace_id、created_at`。

### 7.5 Trace 成本与脱敏规则

`agent_trace` 与 `agent_tool_call` 字段同时承担两件事：业务可追溯性与成本评估。落库与保留策略：

- `token_input`、`token_output`、`cost_ms` 用于模型调用成本估算；
- `truncated` 用于控制大工具输出的存储增长，截断时需保留原始大小或摘要；
- Trace 存储成本是 PM-Agent 运行成本的一部分，估算时不只看 LLM token，也要看 MySQL 增长；
- 敏感字段（手机号、邮箱、token、密码、隐私字段）必须脱敏后入库；
- Trace 默认保留 3 个月，超大原文在第 6 阶段引入 MinIO 后可外挂存储，Trace 表只保留引用路径；
- 估算公式参考：`日均会话数 × 每会话平均工具调用数 × 单条 Trace 平均大小 × 90 天`。

## 10. 第 1 阶段初始化数据

第 1 阶段使用 Flyway 管理数据库迁移脚本，并初始化一组最小演示数据，用于登录、项目列表和任务看板联调。

| 数据类型 | 初始化内容 | 用途 |
|---|---|---|
| 默认用户 | 1 个启用状态用户 | 验证登录、当前用户、项目负责人和任务负责人 |
| 示例项目 | 1 个进行中的项目 | 验证项目列表、项目详情和任务归属 |
| 项目成员 | 默认用户加入示例项目 | 验证项目成员关系和后续权限扩展 |
| 示例任务 | 若干覆盖不同状态的任务 | 验证任务列表、看板分组和状态切换 |
| 任务状态日志 | 示例任务初始状态记录 | 验证状态流转记录结构 |

初始化数据只服务本地开发和演示，生产环境不得直接使用默认账号密码。
