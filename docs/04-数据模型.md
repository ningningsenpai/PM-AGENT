# 数据模型

## 1. 所有权

业务库由 Python SQLAlchemy 访问，结构由 `agent-service/migrations/` 独占管理。本次迁移创建空的开发库基线，不迁移旧 Flyway 数据。

## 2. `pm_user`

| 字段 | 说明 |
|---|---|
| `id` | `BIGINT` 主键，由后端雪花算法生成 |
| `username` | 唯一用户名 |
| `password_hash` | Argon2 密码哈希 |
| `email` | 唯一登录邮箱 |
| `status` | `enabled` / `disabled` |
| `last_login_at` | 最近登录时间 |
| `created_at` / `updated_at` | 审计时间 |

## 3. `pm_project`

| 字段 | 说明 |
|---|---|
| `id` | `BIGINT` 主键，由后端雪花算法生成 |
| `owner_user_id` | 所属用户，外键到 `pm_user` |
| `project_name` | 项目名称 |
| `status` | `initializing` / `active` / `init_failed` |
| `record_status` | 记录状态：`active` / `inactive`，用于惰性删除 |
| `created_at` / `updated_at` | 审计时间 |

`owner_user_id + project_name` 唯一；删除用户级联删除所属项目。业务删除项目时只把 `record_status` 更新为 `inactive`，项目列表、详情、文件和 Agent 入口均把该记录视为不存在，不删除项目文件行或 MinIO 对象。再次创建同一用户的同名项目时恢复原记录并保留原项目 ID 与上下文。

`pm_user.id` 和 `pm_project.id` 保留 `BIGINT` 存储，但不再使用数据库自增。历史 ID 保持不变，新记录由后端雪花算法生成；不同运行实例必须配置不同的 `PM_AGENT_SNOWFLAKE_NODE_ID`。

## 4. `pm_project_file`

| 分类 | 字段 |
|---|---|
| 归属 | `id`、`project_id`、`business_code` |
| 逻辑路径 | `relative_path`、`path_hash`、`file_name`、`extension` |
| 对象存储 | `storage_uuid`、`storage_name`、`object_key`、`minio_path` |
| 内容事实 | `content_type`、`size_bytes`、`source_mtime_ms`、`quick_fingerprint`、`content_hash` |
| 状态机 | `status`、`upload_status`、`upload_attempts`、`lock_version` |
| 分析投影 | `parse_attempts`、`detail_ref`、`module`、`kind`、`file_type`、`language`、`importance`、`summary`、`keywords` |
| 诊断 | `last_error_code`、`last_error_message`、`last_failed_at` |
| 审计 | `created_at`、`updated_at` |

关键唯一约束：

- `project_id + business_code + path_hash`
- `object_key`
- `project_id + business_code + storage_name`
- `project_id + storage_uuid`

文件生命周期状态：

```text
uploading / active / updating / upload_failed /
verify_required / missing / deleting / delete_failed
```

上传事实状态：

```text
not_uploaded / retrying / success / failed
```

只有用户记录被物理删除时，外键才会级联删除项目和文件记录。项目业务删除为惰性删除，不触发级联删除或 MinIO 对象清理。

`detail_ref` 为空表示当前内容或路径尚无有效详情。分析成功后写入引用；内容或路径变化时清空引用和分析投影。`content_hash` 与 `lock_version` 共同保护分析结果回填，不再保存或比较分析管线版本。

## 5. 迁移

```bash
cd agent-service
python -m alembic upgrade head
python -m alembic downgrade base
```

历史迁移一旦应用不得直接修改；后续结构变更必须新增 Alembic revision。
