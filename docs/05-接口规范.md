# 05 接口规范

## 1. 背景

当前 Java 后端提供多用户认证、当前用户资料、最小项目归属和项目文件接口，不包含租户隔离。本文档定义统一响应、错误、traceId、认证和日志规则。

项目文件单文件上传规则以 [18-项目文件可靠上传模块设计](./18-项目文件可靠上传模块设计.md) 为准。

## 2. 通用目标

- 业务接口统一使用 `/api/v1`；
- 所有响应使用 `R<T>`；
- 响应和访问日志使用同一 `traceId`；
- 密码、哈希、token 和完整文件内容不进入日志。

## 3. 路径与接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|

## 4. 请求头

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 登录后必填 | Sa-Token JWT，格式为 `Bearer <token>` |
| `X-Trace-Id` | Java 业务接口可选；Python 文件解析接口必填 | Java 未收到时生成并透传给 Python |
| `X-Idempotency-Key` | 文件上传和覆盖请求必填 | 长度 1～64；重复提交按接口幂等规则处理 |
| `X-Internal-Service-Token` | Python 文件解析接口必填 | Java 与 Python 之间的内部服务认证令牌 |

当前没有租户，不使用 `X-Tenant-Id`。用户身份只从登录态读取，不接受前端用户 ID 作为权限依据。

## 5. 单文件上传接口

### 5.1 请求

```http
POST /api/v1/projects/10/files
Authorization: Bearer <token>
X-Idempotency-Key: 76f4ee2e-5a7d-4b20-9ee5-88f99a670c64
Content-Type: multipart/form-data
```

| Multipart 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | File | 是 | 当前单个文件 |
| `relativePath` | String | 是 | 项目根目录内相对路径，最长 512 |
| `sourceMtimeMs` | Long | 是 | 源文件最后修改时间，不能小于 0 |

请求中不再包含 `manifest`、`batch`、文件数组、上传轮次或客户端文件 ID。

### 5.2 成功结果

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "fileId": 101,
    "relativePath": "backend/src/main/App.java",
    "fileName": "App.java",
    "success": true,
    "status": "active",
    "uploadStatus": "success",
    "errorCode": null,
    "errorMessage": null
  },
  "traceId": "abc123def456"
}
```

### 5.3 MinIO 失败结果

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "fileId": 101,
    "relativePath": "backend/src/main/App.java",
    "fileName": "App.java",
    "success": false,
    "status": "uploading",
    "uploadStatus": "not_uploaded",
    "errorCode": "FILE_STORAGE_ERROR",
    "errorMessage": "文件存储服务异常"
  },
  "traceId": "abc123def456"
}
```

MinIO 失败是文件级已处理结果，因此统一响应外层仍成功，前端根据 `data.success` 收集结果。参数、权限、路径冲突和数据库异常使用非零统一错误响应。

## 6. 文件解析接口

### 6.1 Java 初始化解析接口

```http
POST /api/v1/projects/10/files/parse/init
Authorization: Bearer <token>
```

当前无请求体。接口只校验当前用户拥有项目并返回：

```json
{
  "code": 0,
  "message": "成功",
  "data": null,
  "traceId": "abc123def456"
}
```

该接口查询 `active` 且 `parse_attempts=0` 的项目文件，批量调用 Python 解析接口。Java 校验响应后按 `detail_ref` 将完整详情写入 MinIO，保存索引投影字段并累加 `parse_attempts`，最后下载、补全并整体覆盖 `system/index.json`。

### 6.2 Python 同步文件解析接口

```http
POST /api/v1/project-files/analyze
X-Trace-Id: <链路追踪 ID>
Content-Type: application/json
```

请求体字段统一使用 camelCase：

```json
[
  {
    "userId": 1,
    "projectId": 10,
    "business": "project",
    "fileId": 101,
    "filename": "README.md",
    "fileUrl": "http://minio.example/pm-agent/project/README.md?<临时签名>",
    "fileType": "markdown",
    "storageUuid": "a1b2c3d4e5f67890",
    "storageName": "README-a1b2c3d4e5f67890.md",
    "detailRef": "system/file_details/README-a1b2c3d4e5f67890.json",
    "originalPath": "docs/README.md",
    "minioPath": "PM-AGENT/1/10/project/README-a1b2c3d4e5f67890.md",
    "sizeBytes": 1024,
    "contentType": "text/markdown",
    "contentHash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "analysisVersion": "file-detail-v1"
  }
]
```

请求体由 Java 提供一组文件 ID、存储元数据、内容哈希、受控只读地址和分析版本。Python 逐个下载文件并校验模型输出，随后同步返回同等数量的 `success` 或 `failed` 结果。该接口不操作 MySQL、不上传 MinIO、不回调 Java，也不使用 MQ。

成功响应核心字段：

```json
[
  {
    "projectId": 10,
    "fileId": 101,
    "contentHash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "analysisVersion": "file-detail-v1",
    "status": "success",
    "detail": {
      "id": "file-101",
      "detail_ref": "system/file_details/README-a1b2c3d4e5f67890.json",
      "module": "docs",
      "kind": "documentation",
      "file_type": "doc",
      "language": "markdown",
      "importance": "medium",
      "summary": "文件职责摘要",
      "keywords": ["项目文件"],
      "content_hash": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    },
    "errorCode": null,
    "errorMessage": null
  }
]
```

下载或结构校验失败时 HTTP 请求仍正常返回，失败项使用 `status=failed`，并通过 `errorCode` 和中文 `errorMessage` 描述文件级失败。

## 7. 统一响应

### 7.1 成功响应

```json
{
  "code": 0,
  "message": "成功",
  "data": {},
  "traceId": "abc123def456"
}
```

### 7.2 失败响应

```json
{
  "code": 10001,
  "message": "参数不合法",
  "data": null,
  "traceId": "abc123def456"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | 0 表示统一响应成功，非 0 表示错误 |
| `message` | string | 中文提示 |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 请求链路标识 |

## 8. 主要错误码

| 错误码 | 名称 | message | 说明 |
|---:|---|---|---|
| 0 | `SUCCESS` | 成功 | 请求成功 |
| 10001 | `PARAM_INVALID` | 参数不合法 | 参数校验或业务参数错误 |
| 10003 | `RESOURCE_CONFLICT` | 资源冲突 | 重复提交或通用资源冲突 |
| 20001 | `UNAUTHORIZED` | 未登录 | 没有有效登录态 |
| 20002 | `FORBIDDEN` | 无权限 | 权限校验失败 |
| 20009 | `SYSTEM_FILE_ACCESS_DENIED` | 系统文件不允许通过公开接口访问 | 公开接口访问 `system` 命名空间 |
| 30001 | `PROJECT_NOT_FOUND` | 项目不存在或无权访问 | 项目不存在或不属于当前用户 |
| 30002 | `PROJECT_DISABLED` | 项目已停用 | 项目不能继续操作 |
| 30010 | `FILE_NOT_FOUND` | 文件不存在或无权访问 | 文件不存在或不属于项目 |
| 30011 | `FILE_PATH_CONFLICT` | 文件路径已存在 | 同一业务类型内路径冲突 |
| 30012 | `FILE_STATUS_INVALID` | 文件当前状态不允许执行该操作 | 状态流转不合法 |
| 30013 | `FILE_BUSY` | 文件正在被其他请求处理 | 乐观锁或状态抢占失败 |
| 30014 | `FILE_TOO_LARGE` | 文件大小超出限制 | 单文件超过 50 MB |
| 30015 | `FILE_EXTENSION_NOT_ALLOWED` | 文件扩展名不允许上传 | 扩展名校验失败 |
| 30016 | `FILE_MIME_TYPE_BLOCKED` | 文件内容类型不允许上传 | MIME 校验失败 |
| 30017 | `FILE_PATH_IGNORED` | 文件路径不允许上传 | 路径规则校验失败 |
| 50001 | `FILE_STORAGE_ERROR` | 文件存储服务异常 | MinIO 调用失败 |
| 50002 | `PROJECT_INDEX_INIT_FAILED` | 项目上下文索引初始化失败 | 创建项目时初始索引上传失败 |

错误码由 `common.errorcode.ErrorCode` 统一维护。

## 9. traceId 与日志

1. `TraceInterceptor` 读取 `X-Trace-Id`；
2. 缺失时生成无连字符 UUID；
3. 写入 MDC 和响应头；
4. `R<T>` 从 `TraceContext` 读取同一 traceId；
5. 请求结束后清理 MDC。

日志不得包含密码、密码哈希、JWT、服务 token 或完整文件内容。

## 10. 权限

- 登录态使用 Sa-Token + JWT；
- 当前只区分匿名和已登录；
- 受保护接口使用 `@SaCheckLogin`；
- Service 通过项目归属校验限制资源访问；
- 不实现租户隔离；
- `system` 是内部命名空间，公开文件接口不允许直接操作系统文件。

## 11. 文档与测试

- 具体认证字段见 [13-用户认证模块设计.md](./13-用户认证模块设计.md)；
- Knife4j 用于浏览和调试，Markdown 文档仍是长期规范；
- 单文件上传至少测试首次落库状态、成功状态更新、MinIO 失败不更新和不触发索引；
- 前端至少通过 TypeScript 检查，确认不存在旧批次类型和接口调用。

## 12. 验收标准

- 所有接口返回统一响应；
- 响应头和响应体 traceId 一致；
- 单文件上传一次只接收一个文件；
- 文件级 MinIO 失败通过 `data.success=false` 返回；
- 初始化解析接口按详情引用上传 MinIO、保存投影字段并补全索引；
- 未登录接口由 Sa-Token 统一拒绝；
- 日志中不存在敏感信息。
