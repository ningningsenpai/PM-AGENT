# 05 接口规范

## 1. 背景

当前 Java 后端提供多用户认证、当前用户资料、最小项目归属和项目文件接口，不包含租户隔离。本文档定义这些接口共同遵循的响应、错误、traceId、认证和日志规则。

## 2. 目标

- 业务接口统一使用 `/api/v1`；
- 所有响应使用 `R<T>`；
- 所有响应和访问日志包含同一条请求链路的 traceId；
- Controller 记录业务入口和成功结果；
- 密码、哈希和 token 不进入日志。

## 3. 路径与接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/internal/health` | 匿名 | 健康检查 |
| `POST` | `/api/v1/auth/register` | 匿名 | 注册用户 |
| `POST` | `/api/v1/auth/login` | 匿名 | 邮箱密码登录 |
| `POST` | `/api/v1/auth/logout` | 登录用户 | 退出登录 |
| `GET` | `/api/v1/users/me` | 登录用户 | 查询当前账户资料 |
| `PUT` | `/api/v1/users/me` | 登录用户 | 修改当前账户资料 |
| `PUT` | `/api/v1/users/me/password` | 登录用户 | 修改当前账户密码 |
| `POST` | `/api/v1/projects` | 登录用户 | 创建项目文件空间并初始化 `system/index.json` |
| `GET` | `/api/v1/projects` | 登录用户 | 查询项目文件空间 |
| `DELETE` | `/api/v1/projects/{projectId}` | 登录用户 | 硬删除项目数据和项目根前缀下全部对象 |
| `POST` | `/api/v1/projects/{projectId}/files` | 登录用户 | 上传单个文件；批次模式通过 multipart 字段 `ingestBatchId` 关联批次 |
| `POST` | `/api/v1/projects/{projectId}/file-ingest-batches` | 登录用户 | 使用筛选后的 `totalFiles` 创建项目文件导入批次 |
| `GET` | `/api/v1/projects/{projectId}/file-ingest-batches/{batchId}` | 登录用户 | 查询上传与详情解析进度 |
| `PUT` | `/api/v1/projects/{projectId}/files/{fileId}/content` | 登录用户 | 覆盖同一稳定UUID对象 |
| `PATCH` | `/api/v1/projects/{projectId}/files/{fileId}/path` | 登录用户 | 修改逻辑路径，文件名变化时迁移MinIO对象 |
| `GET` | `/api/v1/projects/{projectId}/files` | 登录用户 | 查询项目文件 |
| `GET` | `/api/v1/projects/{projectId}/files/{fileId}/read-url` | 登录用户 | 获取五分钟只读地址 |
| `DELETE` | `/api/v1/projects/{projectId}/files/{fileId}` | 登录用户 | 删除文件和对象 |
| `GET` | `/api/v1/agent/projects/{projectId}/files/{fileId}/read-url` | Python Agent 内部身份 | 为详细解析刷新短期只读地址 |
| `PUT` | `/api/v1/agent/projects/{projectId}/files/{fileId}/analysis-result` | Python Agent 内部身份 | 回传结构化解析结果，由 Java 写入详情对象和数据库 |

业务接口使用 `/api/v1/<module>/<resource>`。健康检查和 Knife4j 等内部接口不使用业务前缀。

## 4. 请求头

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Authorization` | 登录后必填 | Sa-Token JWT，格式为 `Bearer <token>` |
| `X-Trace-Id` | 否 | 调用方可传；未传时由后端生成并写回响应头 |
| `X-Idempotency-Key` | 所有写接口必填 | 长度1到64；同一调用方、同一操作范围内重复请求返回同一业务结果 |

当前没有租户，不使用`X-Tenant-Id`。用户身份只从Sa-Token登录态读取，不接受前端传入用户ID作为权限依据。

Agent 内部接口还必须携带 `X-Internal-Service-Token` 校验服务身份。服务凭证不得放入查询参数、MQ 消息体或日志；内部调用继续透传 `X-Trace-Id`。

### 4.1 文件解析接口说明

文件导入批次、预签名地址刷新和解析结果回调的 DTO、幂等条件及异常分支详见 [19-项目上下文索引与MinIO存储设计.md](./19-项目上下文索引与MinIO存储设计.md)。Python 回调通过路径携带 `projectId/fileId`，请求体携带 `eventId`、`batchId`、`contentHash`、`analysisVersion`、解析状态和完整详情对象；`X-Idempotency-Key` 必须等于 `eventId`。批次模式下 `batchId` 必须与文件当前导入批次一致，兼容的非批次单文件模式使用 `null`。Java 必须拒绝内容哈希或稳定身份不匹配的旧结果。

## 5. 统一响应

### 5.1 成功响应

```json
{
  "code": 0,
  "message": "成功",
  "data": {},
  "traceId": "abc123def456"
}
```

### 5.2 失败响应

```json
{
  "code": 20004,
  "message": "邮箱或密码错误",
  "data": null,
  "traceId": "abc123def456"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | 0 表示成功，非 0 表示错误 |
| `message` | string | 中文提示 |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 请求链路标识 |

## 7. traceId 与日志

### 7.1 traceId

1. `TraceInterceptor` 读取 `X-Trace-Id`；
2. 缺失时生成无连字符 UUID；
3. 写入 MDC 和响应头；
4. `R<T>` 从 `TraceContext` 读取同一 traceId；
5. 请求结束后清理 MDC。

### 7.2 MDC 字段

| 字段 | 说明 |
|---|---|
| `traceId` | 请求链路标识 |
| `userId` | 当前用户 ID，匿名请求为 `-` |
| `action` | HTTP 方法和请求路径 |
| `costMs` | 请求处理耗时 |

### 7.3 日志责任

- Controller：记录业务请求进入和成功完成；
- `GlobalExceptionHandler`：记录业务异常、参数异常和系统异常；
- `TraceInterceptor`：记录 HTTP 状态和耗时；
- Service：默认不重复记录 Controller 入口日志。

日志不得包含密码、密码哈希、JWT token 或完整请求体。

## 8. 权限

- 登录态使用 Sa-Token + JWT；
- 当前只区分匿名和已登录；
- 受保护接口使用 `@SaCheckLogin`；
- Controller 通过 `CurrentUserHolder` 获取当前用户 ID；
- 不实现 RBAC、租户隔离或手写 Service 鉴权。
- `system` 是内部命名空间，公开文件接口不允许上传、覆盖、读取、列出或删除系统文件。

## 9. 文档与测试

- 具体认证请求、响应字段见 [13-用户认证模块设计.md](./13-用户认证模块设计.md)；
- Knife4j 用于浏览和调试，Markdown 文档仍是长期规范；
- Controller 测试至少覆盖统一响应和参数校验；
- Service 测试覆盖登录失败、禁用账户、用户字段冲突，以及索引初始化、文件新增重试、同键覆盖、相同内容跳过、路径移动和文件重命名迁移。

## 10. 验收标准

- 所有接口返回统一响应；
- 响应头和响应体 traceId 一致；
- 未登录接口由 Sa-Token 统一拒绝；
- Controller 输出业务日志；
- 系统异常保留堆栈，业务异常只记录 WARN；
- 日志中不存在密码、哈希或 token。
