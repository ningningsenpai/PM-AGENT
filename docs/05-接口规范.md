# PM-Agent 接口规范

## 1. 当前边界

当前后端是 FastAPI 模块化单体，业务接口统一使用 `/api/v1` 前缀。MySQL 只保存用户、项目、项目文件身份、会话、消息、Agent 运行、待确认草稿和报告；项目当前有效的 Index、Detail、规则、长短期记忆与项目级用户偏好正文保存在 MinIO `system/` 目录。

任务看板与风险中心当前只保留前端未开放页面，后端不提供任务实体、风险实体、动作草稿或对应状态机接口。

## 2. 通用约定

### 2.1 认证

除注册、登录外，接口使用：

```http
Authorization: Bearer <access_token>
```

写接口可使用：

```http
X-Idempotency-Key: <稳定幂等键>
X-Trace-Id: <调用方链路标识>
```

### 2.2 响应

普通业务接口统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "链路标识"
}
```

错误响应使用中文 `message`，并保持相同外层结构。流式对话使用 SSE 事件，但最终结果仍携带可追踪的运行标识与上下文更新结果。

### 2.3 ID 与时间

- 业务 ID 在 JSON 中按字符串传递，避免 JavaScript 整数精度丢失。
- 时间使用带时区的 ISO 8601 字符串。
- 文件正文哈希使用 SHA-256。

## 3. 认证与用户

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/auth/register` | 注册 |
| `POST` | `/api/v1/auth/login` | 登录并创建 Redis 会话 |
| `POST` | `/api/v1/auth/logout` | 注销当前 JWT 会话 |
| `GET` | `/api/v1/users/me` | 获取当前用户 |
| `PUT` | `/api/v1/users/me` | 更新当前用户资料 |
| `PUT` | `/api/v1/users/me/password` | 修改密码 |

## 4. 项目与项目文件

### 4.1 项目

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/projects` | 创建项目并初始化 MinIO `system/` 快照 |
| `GET` | `/api/v1/projects` | 获取当前用户的项目列表 |
| `GET` | `/api/v1/projects/{projectId}` | 获取项目详情 |
| `DELETE` | `/api/v1/projects/{projectId}` | 删除项目 |

项目创建成功后必须存在 15 个初始系统对象：Index、规则清单、五个规则分区、长短期记忆、五个项目级用户习惯分区和更新日志。

### 4.2 文件管理

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/projects/{projectId}/files` | 上传项目文件 |
| `PUT` | `/api/v1/projects/{projectId}/files/{fileId}/content` | 覆盖文件正文 |
| `PATCH` | `/api/v1/projects/{projectId}/files/{fileId}/path` | 修改相对路径 |
| `GET` | `/api/v1/projects/{projectId}/files` | 查询文件列表 |
| `GET` | `/api/v1/projects/{projectId}/files/{fileId}/read-url` | 获取临时读取地址 |
| `DELETE` | `/api/v1/projects/{projectId}/files/{fileId}` | 删除文件 |
| `POST` | `/api/v1/projects/{projectId}/files/sync/plan` | 计算客户端目录与服务端文件差异 |

项目文件 MySQL 记录只保存身份、路径、哈希、解析状态和 MinIO 引用，不保存规则或记忆正文。

### 4.3 文件解析

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/projects/{projectId}/files/parse/init` | 解析选定或待解析文件并更新上下文快照 |
| `POST` | `/api/v1/projects/{projectId}/files/parse/recover` | 查询或恢复解析运行 |

解析结果核心格式：

```json
{
  "runId": "运行标识",
  "status": "success | partial",
  "candidateCount": 2,
  "successCount": 2,
  "failureCount": 0,
  "failures": [],
  "specificationStatus": "updated | kept | failed",
  "indexStatus": "updated | failed",
  "memoryStatus": "updated | kept | failed"
}
```

解析顺序为：文件正文与身份确认 → Detail → 按文件来源增量同步五类规则 → 长期记忆事实对账 → 最终 Index。上传时命中规则路径的文件预先获得规则来源资格；模型只能用 `may_supply_project_constraints=true` 补充授予资格，不能用 `false` 撤销已有资格。取得资格且解析成功的文件，按 Detail 的五个 `rule_candidates` 分区覆盖自身 `file_id` 规则组。`project_facts` 仍只用于长期记忆兼容链路，不再进入项目规范。

## 5. Agent 对话

### 5.1 会话和消息

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/agent/conversations` | 创建项目会话 |
| `GET` | `/api/v1/agent/conversations` | 查询会话列表 |
| `GET` | `/api/v1/agent/conversations/{conversationId}/messages` | 查询消息 |
| `PATCH` | `/api/v1/agent/conversations/{conversationId}` | 重命名会话 |
| `POST` | `/api/v1/agent/conversations/{conversationId}/messages` | 发送消息并启动多维理解、更新、召回和回答 |
| `GET` | `/api/v1/agent/tools` | 查询当前对话可用的只读工具 |
| `GET` | `/api/v1/agent/runs/{runId}` | 查询 Agent 运行状态 |
| `POST` | `/api/v1/chat` | 旧客户端兼容入口 |

消息完成结果中的 `contextUpdate` 采用以下状态：

```json
{
  "status": "not_requested | applied | pending_confirmation | applied_and_pending | failed",
  "appliedCount": 0,
  "pendingDraftId": null,
  "targets": [],
  "errors": []
}
```

- 用户明确说“设为本项目规则/偏好/目标”且模型置信度达到阈值时，可在同轮直接更新对应 MinIO 文件。
- 表达不明确时只创建待确认草稿，确认前不得修改正式快照。
- 普通问答不得因为命中规则或偏好而产生持久化更新。

### 5.2 待确认草稿

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/agent/learning-drafts` | 查询自动识别出的待确认草稿 |
| `GET` | `/api/v1/agent/learning-drafts/{draftId}` | 获取草稿详情 |
| `PATCH` | `/api/v1/agent/learning-drafts/{draftId}` | 编辑草稿候选 |
| `POST` | `/api/v1/agent/learning-drafts/{draftId}/refine` | 让模型基于用户补充重新整理 |
| `POST` | `/api/v1/agent/learning-drafts/{draftId}/confirm` | 确认并写入 MinIO 正式文件 |
| `POST` | `/api/v1/agent/learning-drafts/{draftId}/rebase` | 当前快照变化后重新生成写入基线 |

不存在“学习本会话”接口。上述草稿只服务于每轮对话中的自动隐式识别和人工确认。

### 5.3 上下文兼容编辑接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/agent/context-entries` | 投影读取当前 MinIO 上下文条目 |
| `PATCH` | `/api/v1/agent/context-entries/{entryId}` | 人工修正一个条目 |
| `GET` | `/api/v1/agent/context-entries/changes` | 查看当前快照的变更投影 |
| `POST` | `/api/v1/agent/context-entries/publish` | 发布兼容编辑结果 |

这些接口不创建 MySQL 上下文真相表；它们通过固定上下文存储读写 MinIO 当前快照。

## 6. 项目报告

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/projects/{projectId}/reports` | 显式生成项目发展或风险分析报告 |
| `GET` | `/api/v1/projects/{projectId}/reports` | 查询报告列表 |
| `GET` | `/api/v1/projects/{projectId}/reports/{reportId}` | 获取报告详情 |

风险报告是分析结果，不等于风险中心实体。当前接口不会创建或推进风险状态机。

## 7. 已移除能力

以下能力不属于当前接口面：

- 任务实体的创建、分配、状态迁移和看板接口；
- 风险实体的创建、处置、关闭和风险中心接口；
- 动作草稿、业务写命令和批量执行接口；
- MySQL 上下文资产、候选、证据和检索投影接口；
- 主动“学习本会话”接口；
- 由代码文件推导项目规则。

## 8. 变更维护

新增或修改接口时必须同步更新本文档。数据库结构变化必须通过新的 Alembic 迁移完成，不得改写已执行迁移。
