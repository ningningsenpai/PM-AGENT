# 05 接口规范

本文档定义 PM-Agent 后端 API 的路径、响应结构、错误码、请求头、幂等、权限和文档维护规则。所有 Java 后端接口、Python Agent 接口和前端 Axios 封装均应遵守本文档。

---

## 1. 背景

PM-Agent 同时包含 Vue 前端、Java 后端和 Python Agent 服务。统一接口规范可以保证：

- 前端能以固定方式处理响应、错误和 traceId；
- Java 与 Python 服务间调用可追踪；
- Agent 工具调用具备权限、幂等和人工确认边界；
- Markdown API 文档与 Knife4j 保持一致。

---

## 2. 路径规范

### 2.1 业务接口前缀

所有业务接口使用：

```text
/api/v1/<module>/<resource>
```

示例：

| 模块 | 示例路径 |
|---|---|
| 认证 | `POST /api/v1/auth/login` |
| 项目 | `GET /api/v1/projects` |
| 任务 | `PUT /api/v1/tasks/{id}/status` |
| 迭代 | `GET /api/v1/iterations` |
| 风险 | `POST /api/v1/risks` |
| Agent | `POST /api/v1/agent/chat` |

### 2.2 非业务接口

以下接口不使用 `/api/v1`：

| 类型 | 路径 |
|---|---|
| 健康检查 | `/actuator/health` 或 `/internal/health` |
| Knife4j | `/doc.html` |
| 静态资源 | 按前端部署规则 |

### 2.3 命名规则

- 路径资源名使用复数：`projects`、`tasks`、`risks`；
- 路径中不使用驼峰，统一小写短横线；
- 动作类接口放在资源后：`/tasks/{id}/status`、`/reports/{id}/publish`；
- 不在路径里使用未进入 `docs/00-术语表.md` 的业务名词。

## 3. 请求头规范

| 请求头 | 必填 | 适用场景 | 说明 |
|---|---|---|---|
| `Authorization` | 登录后必填 | 所有需登录接口 | Sa-Token JWT |
| `X-Trace-Id` | 否 | 所有接口 | 前端可传；后端未收到时生成并返回 |
| `X-Idempotency-Key` | 写接口必填 | `POST` / `PUT` / `PATCH` / `DELETE` | 防重复提交 |
| `X-Tenant-Id` | 内部调用可传 | Java ↔ Python | 第 1 阶段固定 0 |
| `X-User-Id` | 内部调用必传 | Java ↔ Python | Agent 工具调用上下文 |

## 4. 统一响应结构

### 4.1 成功响应

```json
{
  "code": 0,
  "message": "成功",
  "data": {},
  "traceId": "abc123def456"
}
```

### 4.2 失败响应

```json
{
  "code": 30001,
  "message": "任务不存在",
  "data": null,
  "traceId": "abc123def456"
}
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | 0 表示成功，非 0 表示错误码 |
| `message` | string | 中文提示信息 |
| `data` | object / array / null | 业务数据，失败时可为 null |
| `traceId` | string | 链路追踪 ID，任何响应都必须返回 |

## 5. 错误码规范

### 5.1 分段

| 段 | 含义 | 示例 |
|---|---|---|
| `0` | 成功 | `0 成功` |
| `1xxxx` | 通用错误 | 参数缺失、参数非法、幂等键缺失 |
| `2xxxx` | 用户与权限 | 未登录、无权限、用户不存在 |
| `3xxxx` | 项目与任务 | 项目不存在、任务状态非法、风险不存在 |
| `4xxxx` | Agent 与 LLM | Agent 服务异常、模型调用失败、工具执行失败 |
| `5xxxx` | 外部服务 | 文件服务、消息队列、第三方服务异常 |
| `9xxxx` | 系统错误 | 未捕获异常、配置错误 |

### 5.2 初始错误码表

| 错误码 | 名称 | message | 说明 |
|---|---|---|---|
| `0` | `SUCCESS` | 成功 | 请求成功 |
| `10001` | `PARAM_INVALID` | 参数不合法 | Jakarta Validation 或业务参数校验失败 |
| `10002` | `IDEMPOTENCY_KEY_MISSING` | 缺少幂等键 | 写接口未传 `X-Idempotency-Key` |
| `10003` | `RESOURCE_CONFLICT` | 资源冲突 | 唯一键冲突、重复创建等 |
| `20001` | `UNAUTHORIZED` | 未登录 | 未携带有效登录态 |
| `20002` | `FORBIDDEN` | 无权限 | 当前用户无操作权限 |
| `20003` | `USER_NOT_FOUND` | 用户不存在 | 用户 ID 无效或已删除 |
| `30001` | `PROJECT_NOT_FOUND` | 项目不存在 | 项目 ID 无效或无权访问 |
| `30002` | `TASK_NOT_FOUND` | 任务不存在 | 任务 ID 无效或无权访问 |
| `30003` | `TASK_STATUS_INVALID` | 任务状态流转不合法 | 非法状态迁移 |
| `30004` | `RISK_NOT_FOUND` | 风险不存在 | 风险 ID 无效或无权访问 |
| `40001` | `AGENT_SERVICE_ERROR` | Agent 服务异常 | Python Agent 服务调用失败 |
| `40002` | `MODEL_CALL_FAILED` | 模型调用失败 | LLM API 失败 |
| `40003` | `TOOL_CALL_FAILED` | 工具调用失败 | Agent 工具执行失败 |
| `40004` | `HUMAN_CONFIRMATION_REQUIRED` | 需要人工确认 | 高风险动作必须确认 |
| `50001` | `EXTERNAL_SERVICE_ERROR` | 外部服务异常 | 文件、消息或第三方服务异常 |
| `90001` | `SYSTEM_ERROR` | 系统异常 | 未捕获异常兜底 |

### 5.3 维护规则

- 错误码统一由 Java 后端 `common.errorcode.ErrorCode` 枚举管理；
- 新增错误码必须同步更新本文档；
- 错误提示必须为中文；
- 不允许多个错误码表达同一语义。

## 6. 幂等规范

### 6.1 适用范围

所有写接口必须携带：

```text
X-Idempotency-Key: <uuid>
```

适用方法：`POST`、`PUT`、`PATCH`、`DELETE`。

### 6.2 前端规则

- 表单打开或动作触发时生成 UUID；
- 同一次提交和重试复用同一个 key；
- 新建一次业务动作时生成新 key。

### 6.3 后端规则

后端以以下维度生成幂等缓存键：

```text
userId + path + X-Idempotency-Key
```

规则：

1. 首次请求：放行并缓存响应；
2. 重复请求：直接返回第一次响应；
3. TTL：10 分钟；
4. 第 1 阶段 Redis 未引入时使用 Caffeine，仅保证单实例幂等；
5. 第 2 阶段 Redis 引入后切换到 Redis。

### 6.4 Agent 工具调用

Agent 调用业务写接口时，由 Java `AgentClient` 或 Python 工具调用层自动生成 `X-Idempotency-Key`，并写入 Trace。

## 7. traceId 与日志

### 7.1 traceId 生成与透传

1. 前端可传 `X-Trace-Id`；
2. 后端未收到时生成 UUID 去横线字符串；
3. 后端响应必须返回 `traceId`；
4. Java 调 Python、Python 调模型、Agent 工具调用均需透传 traceId。

### 7.2 MDC 字段

后端日志 MDC 固定字段：

| 字段 | 说明 |
|---|---|
| `traceId` | 链路追踪 ID |
| `userId` | 当前用户 ID，未登录为 `-` |
| `tenantId` | 第 1 阶段固定 0 |
| `action` | 操作标识，如 `task.create` |
| `costMs` | 请求耗时 |

---

## 8. 权限规范

- 登录态使用 Sa-Token + JWT；
- 第 1 阶段只区分登录 / 未登录；
- 第 2 阶段引入 RBAC；
- Controller 使用 `@SaCheckLogin` / `@SaCheckPermission`；
- Service 不手写鉴权逻辑；
- Agent 工具调用必须以用户身份执行，不能使用系统超级权限绕过规则。

---

## 9. Agent 工具接口规范

工具接口必须声明：

| 字段 | 说明 |
|---|---|
| 工具名 | 如 `query_task_list` |
| 所属阶段 | 第 4 阶段起 |
| 输入 Schema | JSON Schema / Pydantic |
| 输出 Schema | JSON Schema / Pydantic |
| 权限要求 | 调用所需权限 |
| 是否写操作 | 决定是否需要幂等键 |
| 是否高风险 | 决定是否需要人工确认 |
| Trace 字段 | 入参、出参、耗时、错误 |
